# 分布式深度学习（Distributed Deep Learning）

*分布式训练将计算分散到多个 GPU 和机器上，以训练对单个设备来说过大或过慢的模型。本文件涵盖混合精度（Mixed Precision）、数据并行（Data Parallelism）、模型并行（Model Parallelism）、流水线并行（Pipeline Parallelism）、ZeRO、FSDP、张量并行（Tensor Parallelism）以及如 all-reduce 等通信原语——这些是大规模训练大语言模型（LLM）所必需的技术。*

- 在单个 GPU 上训练大型神经网络最终会遇到瓶颈。模型可能放不进内存，或者训练可能需要数月。分布式训练将工作分散到多个设备（GPU、TPU 或整台机器）上，以实现更快地训练和训练更大的模型。本文件涵盖使之成为可能的技术。

- 要理解为什么分布式很重要，从训练的**计算代价（Computational Cost）** 开始。在一个包含 $d_{\text{in}}$ 个输入和 $d_{\text{out}}$ 个输出的密集层上，对 $B$ 个样本的批次进行一次前向传播大约需要 $2 \cdot B \cdot d_{\text{in}} \cdot d_{\text{out}}$ FLOPs（浮点运算次数）：对输出矩阵的每个元素进行一次乘法和一次加法。反向传播的代价大约是前向传播的两倍（需要计算对输入和权重的梯度），因此一个密集层的一个训练步骤大约需要 $6 \cdot B \cdot d_{\text{in}} \cdot d_{\text{out}}$ FLOPs。

- 对于一个隐藏维度为 $d$ 的 Transformer 层，自注意力块涉及四个投影（Q、K、V 和输出），每个大约消耗 $O(B \cdot n \cdot d^2)$ FLOPs（其中 $n$ 是序列长度），加上注意力矩阵计算，消耗 $O(B \cdot n^2 \cdot d)$。前馈块有两个密集层，通常先扩展到 $4d$ 再压缩回来：$O(B \cdot n \cdot 8d^2)$。每层总计：大约 $O(B \cdot n \cdot 12d^2 + B \cdot n^2 \cdot d)$。乘以层数，你就会明白为什么训练 GPT 规模的模型需要数千 GPU-小时。

- **内存墙（Memory Wall）** 通常是更紧的约束。在训练期间，GPU 内存必须同时保存四种内容：

![堆叠条形图显示训练内存分解：参数、梯度、优化器状态、激活值](../../images/training_memory_breakdown.svg)

- **参数（Parameters）**：模型权重。一个70亿参数模型在 FP32（每参数4字节）下仅权重就需要28 GB。
- **梯度（Gradients）**：与参数大小相同。另外28 GB。
- **优化器状态（Optimizer States）**：Adam 维护两个额外的缓冲区（一阶和二阶矩估计），每个与参数大小相同。即使模型使用较低精度，这些也保持 FP32 以确保数值稳定性。对于我们的7B模型，这是 $2 \times 28 = 56$ GB。
- **激活值（Activations）**：在前向传播过程中保存的、供反向传播使用的中间值。大小取决于批次大小、序列长度和模型宽度。这通常是最大的组成部分，随批次大小线性增长。

- 对于使用 FP32 Adam 的7B模型：28（参数）+ 28（梯度）+ 56（优化器）= 112 GB，在算入激活值之前就已如此。单个80 GB A100 GPU 无法容纳这些。这就是分布式策略必不可少的原因。

- **混合精度训练（Mixed Precision Training）** 是第一道防线。你不是将所有内容都以 FP32（32位浮点）存储，而是在前向和后向传播中使用 FP16 或 BF16（16位）进行训练，同时保留一份 FP32 的主权重副本用于优化器更新。

- **FP16** 具有高精度（10位尾数）但范围有限，可能导致上溢/下溢。损失缩放（Loss Scaling，在前向传播前将损失乘以一个大因子，然后在反向传播后将梯度除以相同因子）缓解了这一点。

- **BF16**（Brain Float，脑浮点）具有与 FP32 相同的指数范围（8位指数）但精度较低（7位尾数）。它几乎不会溢出，很少需要损失缩放，因此使用更简单。BF16 是现代 Transformer 训练的默认选择。

- 混合精度大约将激活值和梯度的内存减半（这是前向/反向传播期间的主要代价），同时将优化器状态保持为 FP32 以确保数值稳定性。

- **数据并行（Data Parallelism）** 是最简单的分布式策略。你在 $N$ 个 GPU 上复制整个模型，将每个小批次分成 $N$ 个相等块，为每个 GPU 发送一个块。每个 GPU 在其块上独立运行前向和后向传播。然后梯度在所有 GPU 上取平均（使用 all-reduce 操作），每个 GPU 更新其模型的本地副本。

- 从模型的角度看，这等价于使用一个大了 $N$ 倍的小批次进行训练。如果每个 GPU 处理大小为 $B$ 的批次，有效批次大小是 $N \cdot B$。

![并排对比：数据并行复制模型并分割数据，模型并行分割模型并共享数据](../../images/data_model_parallelism.svg)

- 梯度平均可以同步或异步进行。**同步 SGD（Synchronous SGD）** 等待所有 GPU 完成后再取平均，确保与单 GPU 训练更大的批次的数学等价性。缺点是，最慢的 GPU（"落后者"）拖累所有人。

- **异步 SGD（Asynchronous SGD）** 让每个 GPU 独立更新共享的参数服务器，无需等待。这消除了落后者问题，但引入了"陈旧梯度"：一个 GPU 可能基于稍微过时的参数计算梯度。陈旧梯度增加噪声并可能减慢收敛。在实践中，具有高效通信的同步 SGD 是首选。

- **梯度累积（Gradient Accumulation）** 是一种在有限硬件上模拟更大批次大小的软件技巧。不是每个小批次做一次更新，而是运行几次前向/反向传播并累积梯度，然后做一次更新。这给出与更大批次相同的结果，而无需更多 GPU 内存来存储激活值（一次只有一个小批次的激活值在内存中）。

- 当模型本身太大而无法放入单个 GPU 时，你需要**模型并行（Model Parallelism）**。主要有两种类型。

- **张量并行（Tensor Parallelism）** 将单个层跨 GPU 分割。一个大的矩阵乘法 $Y = XW$ 可以按列分割：将 $W$ 分块为 $[W_1, W_2]$ 跨两个 GPU，并行计算 $Y_1 = XW_1$ 和 $Y_2 = XW_2$，然后拼接。这适用于注意力投影和前馈层。它需要在 GPU 之间进行快速通信（通常是节点内的 NVLink），因为每层都必须组合部分结果。

- **流水线并行（Pipeline Parallelism）** 将不同的层分配给不同的 GPU。GPU 0 运行第1-4层，GPU 1 运行第5-8层，依此类推。数据像流水线一样流过。朴素的方法有"流水线气泡"：当 GPU 0 处理微批次1的前向传播时，GPU 1-3 闲置等待。**微批次（Micro-Batching）** 通过将小批次分成更小的微批次来缓解这个问题，微批次按顺序流过流水线，使所有 GPU 大部分时间保持忙碌。

- **混合并行（Hybrid Parallelism）** 结合了数据、张量和流水线并行。一个典型的大模型设置可能在节点内使用张量并行（8个 GPU 通过快速 NVLink 连接），跨节点使用流水线并行，跨节点组使用数据并行。这就是 GPT-4 和 Llama 等模型的训练方式。

- 分布式训练的效率在很大程度上依赖于**通信（Communication）**。关键操作是 **all-reduce**：给定 $N$ 个 GPU 上各有一个值，计算总和（或平均）并将结果分发到所有 GPU。

- 朴素的 all-reduce 将所有数据发送到一个 GPU，求和，然后广播回去。这是 $O(N)$ 的通信量，并在根节点产生瓶颈。

- **环形 all-reduce（Ring All-Reduce）** 效率高得多。将 $N$ 个 GPU 排列成环。每个 GPU 将其数据分成 $N$ 块。在 $N-1$ 步中，每个 GPU 向邻居发送一块并接收一块，累积部分和。再经过 $N-1$ 步，完整和传播到所有 GPU。每个 GPU 传输的总数据量：数据大小的 $2(N-1)/N$ 倍，随着 $N$ 增长趋近于 $2\times$。关键的是，这不随 $N$ 增加，因此是带宽最优的。

![四个 GPU 排列成环，每个向邻居传递梯度块直到所有 GPU 获得完整总和](../../images/ring_allreduce.svg)

- **参数服务器（Parameter Servers）** 是另一种架构，专用服务器节点保存模型参数。工作节点计算梯度并将其发送到服务器，服务器更新参数并发送回。这更简单，但可能在服务器处产生通信瓶颈。

- **NCCL**（NVIDIA Collective Communications Library，NVIDIA 集合通信库）是 GPU 间通信的标准库。它提供了 all-reduce、all-gather、broadcast 和其他集合操作的优化实现，自动为网络拓扑选择最佳算法。

- **缩放定律（Scaling Laws）** 描述了模型性能如何随计算量、数据量和模型大小提升。原始 Kaplan et al. (2020) 缩放定律发现损失随每个因素的幂律下降：

$$L(N) \propto N^{-\alpha_N}, \quad L(D) \propto D^{-\alpha_D}, \quad L(C) \propto C^{-\alpha_C}$$

- 其中 $N$ 是参数数量，$D$ 是数据集大小，$C$ 是计算预算。

- **Chinchilla 缩放定律**（Hoffmann et al., 2022）表明大多数模型训练不足：对于给定的计算预算，你应该在更多数据上训练更小的模型，而非先前认为的那样。最优比率大约是每参数20个标记。一个7B模型应该在大约140B标记上训练，而不是 Llama 1 在65B模型上使用的300B标记。这一发现将领域转向了"计算最优"训练。

- **混合专家（Mixture of Experts，MoE）** 是一种扩展模型容量而不按比例扩展计算量的架构。不是每个 Transformer 层有一个前馈网络，而是有 $N$ 个"专家"网络（每个是一个标准 FFN）。一个**门控网络（Gating Network）**（路由器）检查每个标记并将其发送到 top-$K$ 个专家（通常 $K = 1$ 或 $K = 2$）。

![标记通过门控网络路由到选定的专家，使用 top-K 稀疏路由和输出的加权组合](../../images/moe_routing.svg)

- 总参数量大得多（因为有 $N$ 个专家），但每个标记的 FLOPs 大致保持不变（因为每个标记只有 $K$ 个专家被激活）。例如，Mixtral 8x7B 共有47B参数，但每次前向传播仅使用约13B，以较小模型的代价提供了大得多的模型的性能。

- MoE 引入了挑战。**负载均衡（Load Balancing）**：如果路由器将大多数标记发送到同一个专家，其他专家就被浪费了。一个辅助损失鼓励均匀路由。**通信（Communication）**：不同的专家可能位于不同的 GPU 上，因此路由标记需要 all-to-all 通信，这很昂贵。

- **容错（Fault Tolerance）** 在训练持续数周或数月并运行在数千个 GPU 上时至关重要。如果单个 GPU 故障，你不想丢失所有进度。**检查点（Checkpointing）** 定期将模型权重、优化器状态和训练状态（学习率、步数、数据位置）保存到磁盘。如果发生故障，你从最后一个检查点重新开始。

- **梯度检查点（Gradient Checkpointing）**（也称激活重计算）是一种内存优化，而非容错机制。在前向传播期间，不是保存所有激活值供反向传播使用，而是只在某些检查点保存激活值。在反向传播期间，你从检查点重新计算缺失的激活值。这是以计算换内存：它使前向传播代价增加约33%，但可以将激活内存减少约 $\sqrt{L}$ 倍（其中 $L$ 是层数）。

- 总而言之，训练一个前沿模型结合了所有这些技术：BF16 混合精度，跨数千个 GPU 的环形 all-reduce 数据并行，节点内张量并行，跨节点流水线并行，梯度检查点以减少内存，MoE 以提高参数效率，以及定期的检查点以容错。系统工程与算法设计同样具有挑战性。

- 总结分布式训练工具箱：

| 技术 | 作用 | 权衡 |
|---|---|---|
| 混合精度（BF16） | 将激活值/梯度内存减半 | 轻微的数值差异 |
| 数据并行 | 跨 GPU 扩展批次大小 | 梯度同步的通信开销 |
| 张量并行 | 跨 GPU 分割层 | 需要快速互联 |
| 流水线并行 | 跨 GPU 分割模型阶段 | 流水线气泡（浪费计算） |
| 梯度累积 | 模拟大批次 | 更慢（多次前向/反向传播） |
| 梯度检查点 | 减少激活值内存 | ~33% 更多计算 |
| 环形 all-reduce | 高效的梯度平均 | 对大模型受带宽限制 |
| MoE | 更大容量，相同 FLOPs | 负载均衡、路由复杂度 |
| 缩放定律 | 指导计算分配 | 经验性的，可能不适用于所有规模 |

## 编程任务（使用 CoLab 或 notebook）

1. 计算一个 Transformer 层的 FLOPs 和内存需求。给定隐藏维度 $d$、序列长度 $n$、批次大小 $B$ 和层数，估计总训练代价。
```python
import jax.numpy as jnp

def transformer_layer_flops(d, n, B):
    """Approximate FLOPs for one transformer layer forward pass."""
    # QKV projections: 3 * (B * n * d * d) * 2 (multiply-add)
    qkv_flops = 3 * 2 * B * n * d * d
    # Attention: (B * n * n * d) * 2 for QK^T, (B * n * n * d) * 2 for attn*V
    attn_flops = 2 * 2 * B * n * n * d
    # Output projection: (B * n * d * d) * 2
    out_flops = 2 * B * n * d * d
    # FFN: two layers, d->4d and 4d->d: 2 * (B * n * d * 4d) * 2
    ffn_flops = 2 * 2 * B * n * d * 4 * d
    return qkv_flops + attn_flops + out_flops + ffn_flops

def transformer_layer_memory(d, n, B, dtype_bytes=2):
    """Approximate activation memory (bytes) for one layer."""
    # QKV: 3 * B * n * d
    qkv_mem = 3 * B * n * d * dtype_bytes
    # Attention weights: B * heads * n * n (approx B * n * n * sizeof)
    attn_mem = B * n * n * dtype_bytes
    # FFN intermediate: B * n * 4d
    ffn_mem = B * n * 4 * d * dtype_bytes
    return qkv_mem + attn_mem + ffn_mem

# Example: GPT-2 scale
d, n, B, L = 1024, 1024, 8, 24
fwd_flops = transformer_layer_flops(d, n, B)
total_flops = 3 * L * fwd_flops  # 3x for forward + backward
act_mem = L * transformer_layer_memory(d, n, B)
param_count = L * (12 * d * d + 13 * d)  # approximate

print(f"Model: d={d}, n={n}, B={B}, L={L}")
print(f"Parameters: {param_count / 1e6:.0f}M")
print(f"FLOPs per step: {total_flops / 1e12:.2f} TFLOPs")
print(f"Activation memory: {act_mem / 1e9:.2f} GB (BF16)")
print(f"Parameter memory (FP32): {param_count * 4 / 1e9:.2f} GB")
print(f"Adam optimizer memory: {param_count * 8 / 1e9:.2f} GB")
print(f"Total training memory: {(param_count * 16 + act_mem) / 1e9:.2f} GB")
```

2. 模拟数据并行训练。将数据集分割到多个"虚拟 GPU"上，独立计算梯度，取平均，验证结果与单 GPU 训练匹配。
```python
import jax
import jax.numpy as jnp

# Simple linear model: y = wx + b
key = jax.random.PRNGKey(0)
X = jax.random.normal(key, (64, 4))
w_true = jnp.array([1.0, -2.0, 3.0, 0.5])
y = X @ w_true + 0.1 * jax.random.normal(key, (64,))

def loss_fn(w, X, y):
    return jnp.mean((X @ w - y) ** 2)

grad_fn = jax.grad(loss_fn)

# Single GPU: full batch gradient
w = jnp.zeros(4)
grad_single = grad_fn(w, X, y)

# Data parallel: split across 4 "GPUs"
n_gpus = 4
chunk_size = len(X) // n_gpus
grads = []
for i in range(n_gpus):
    X_chunk = X[i*chunk_size:(i+1)*chunk_size]
    y_chunk = y[i*chunk_size:(i+1)*chunk_size]
    grads.append(grad_fn(w, X_chunk, y_chunk))

# All-reduce: average gradients
grad_parallel = jnp.mean(jnp.stack(grads), axis=0)

print("Single-GPU gradient:", grad_single)
print("Data-parallel gradient (avg):", grad_parallel)
print(f"Match: {jnp.allclose(grad_single, grad_parallel, atol=1e-5)}")

# Train both and compare
w_single, w_parallel = jnp.zeros(4), jnp.zeros(4)
lr = 0.1
for step in range(100):
    w_single = w_single - lr * grad_fn(w_single, X, y)

    grads = [grad_fn(w_parallel, X[i*chunk_size:(i+1)*chunk_size],
                     y[i*chunk_size:(i+1)*chunk_size]) for i in range(n_gpus)]
    avg_grad = jnp.mean(jnp.stack(grads), axis=0)
    w_parallel = w_parallel - lr * avg_grad

print(f"\nAfter 100 steps:")
print(f"Single-GPU weights: {w_single}")
print(f"Data-parallel weights: {w_parallel}")
print(f"Max difference: {jnp.max(jnp.abs(w_single - w_parallel)):.2e}")
```

3. 实现一个简单的混合专家（MoE）层。创建一个将标记路由到 top-K 个专家的门控网络，并组合它们的输出。
```python
import jax
import jax.numpy as jnp

def expert_fn(x, W1, b1, W2, b2):
    """Simple 2-layer FFN expert."""
    h = jnp.maximum(0, x @ W1 + b1)  # ReLU
    return h @ W2 + b2

def moe_layer(x, gate_W, experts_params, top_k=2):
    """
    MoE forward pass.
    x: (batch, d_model)
    gate_W: (d_model, n_experts)
    experts_params: list of (W1, b1, W2, b2) per expert
    """
    n_experts = len(experts_params)

    # Gating: compute routing scores
    gate_logits = x @ gate_W  # (batch, n_experts)
    gate_probs = jax.nn.softmax(gate_logits, axis=-1)

    # Top-K selection
    top_k_indices = jnp.argsort(-gate_probs, axis=-1)[:, :top_k]
    top_k_probs = jnp.take_along_axis(gate_probs, top_k_indices, axis=-1)
    # Renormalise
    top_k_probs = top_k_probs / jnp.sum(top_k_probs, axis=-1, keepdims=True)

    # Compute expert outputs (simplified: run all experts, mask later)
    expert_outputs = jnp.stack([
        expert_fn(x, *experts_params[i]) for i in range(n_experts)
    ], axis=1)  # (batch, n_experts, d_model)

    # Gather top-K expert outputs and weight them
    batch_idx = jnp.arange(x.shape[0])[:, None]
    selected_outputs = expert_outputs[batch_idx, top_k_indices]  # (batch, top_k, d_model)
    output = jnp.sum(selected_outputs * top_k_probs[:, :, None], axis=1)

    return output, gate_probs

# Setup
key = jax.random.PRNGKey(42)
batch, d_model, d_ff, n_experts = 8, 16, 32, 4

# Initialise experts
experts_params = []
for i in range(n_experts):
    k1, k2, key = jax.random.split(key, 3)[0], jax.random.split(key, 3)[1], jax.random.split(key, 3)[2]
    experts_params.append((
        jax.random.normal(k1, (d_model, d_ff)) * 0.1,
        jnp.zeros(d_ff),
        jax.random.normal(k2, (d_ff, d_model)) * 0.1,
        jnp.zeros(d_model),
    ))

key, subkey = jax.random.split(key)
gate_W = jax.random.normal(subkey, (d_model, n_experts)) * 0.1
x = jax.random.normal(key, (batch, d_model))

output, gate_probs = moe_layer(x, gate_W, experts_params, top_k=2)

print(f"Input shape: {x.shape}")
print(f"Output shape: {output.shape}")
print(f"Gate probabilities (first sample): {gate_probs[0]}")
print(f"Expert usage (avg across batch):")
for i in range(n_experts):
    usage = jnp.mean(gate_probs[:, i])
    print(f"  Expert {i}: {usage:.3f}")
```
