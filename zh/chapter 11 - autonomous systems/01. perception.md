# 感知（Perception）

*感知是自主系统（autonomous systems）如何感知和解释物理世界的。本文件涵盖传感器模态、标定、传感器融合、3D 目标检测、深度估计、占用网络、车道检测和语义建图——这些是每个机器人、无人机和自动驾驶汽车所依赖的感知基础。*

- 对于人类来说，感知世界毫不费力：你看到一辆车驶来，听到它的引擎声，感受到脚下的地面，并立即构建出周围环境的心理模型。自主系统必须做同样的事情，但使用的是电子传感器和算法，而不是眼睛和耳朵。

- 根本挑战在于：传感器提供原始数字（像素强度、点云、信号反射），系统必须将这些数字转化为结构化的理解："前方 12 米处有一个行人，正以 1.5 m/s 的速度向左移动。"这就是感知问题。

- 下游的一切（预测、规划、控制）都依赖于感知。一辆拥有完美规划器但感知很差的自动驾驶汽车仍然会撞车。感知是瓶颈。

## 传感器模态（Sensor Modalities）

- 自主系统使用多种传感器类型，每种都有不同的优势和失效模式。没有一种传感器能独善其身。

![传感器对比：相机、LiDAR、雷达和IMU在分辨率、深度、天气鲁棒性、速度测量和成本方面的评级](../../images/sensor_comparison.svg)

- **相机**（Cameras）以高分辨率捕获密集的颜色信息。单张图像包含数百万个像素，每个像素记录 RGB 值（如我们在第 8 章所见）。相机便宜、轻便，并提供丰富的纹理和颜色信息，这对于读取路标、检测交通灯和识别物体至关重要。

- 相机类型包括**单目**（monocular，单镜头，无原生深度）、**立体**（stereo，两个镜头由基线分隔，通过视差获取深度，如第 8 章所述）和**鱼眼**（fisheye，超广角视场，180°以上，具有严重的径向畸变，用于环视泊车系统）。

- 相机的主要弱点是它们在投影过程中丢失了深度信息。3D 场景通过针孔相机模型映射到 2D 图像平面（回顾第 8 章的内参矩阵 $K$）：

$$\begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = \frac{1}{Z} K \begin{bmatrix} X \\ Y \\ Z \end{bmatrix}$$

- 除以 $Z$ 丢弃了绝对深度。两个不同大小、位于不同距离的物体可以产生相同的投影。从单张图像中恢复深度是一个不适定（ill-posed）问题，这就是为什么需要立体相机或学习的单目深度模型。

- 相机在恶劣条件下也会挣扎：直射阳光造成眩光，黑暗降低信号，雨或雾会散射光线。

- **LiDAR**（光探测与测距，Light Detection and Ranging）发射激光脉冲并测量每个脉冲反弹回来的时间。由于光以已知速度（$c \approx 3 \times 10^8$ m/s）传播，到每个反射点的距离为：

$$d = \frac{c \cdot \Delta t}{2}$$

![LiDAR 飞行时间：激光脉冲从物体上反弹，距离由往返时间计算得出](../../images/lidar_time_of_flight.svg)

- 因子 2 考虑了往返行程（去和回）。通过在场景中扫描激光，LiDAR 构建出一个**点云**（point cloud）：一组 3D 坐标 $(x, y, z)$，通常带有强度（反射率）值。

- **旋转式 LiDAR**（Spinning LiDAR，例如 Velodyne）将激光阵列旋转 360° 以产生完整的环视视图。典型单元每秒产生 300,000+ 个点，跨越 64-128 个垂直通道。结果是对场景的稀疏但在几何上精确的 3D 表示。

- **固态 LiDAR**（Solid-state LiDAR）没有移动部件，而是使用光学相控阵或 MEMS 镜。这使得它们更便宜、更紧凑、更可靠，但通常视场较窄（120° 对比 360°）。

- LiDAR 提供精确的深度，但产生的数据稀疏（比相机少得多的"像素"），没有颜色信息，且价格昂贵。它在大雨、雪或灰尘中也会退化，因为颗粒会散射激光脉冲。

- **雷达**（Radar，无线电探测与测距）与 LiDAR 基于相同的飞行时间原理，但使用无线电波（毫米波，汽车雷达通常为 77 GHz）。无线电波穿透雨、雾、灰尘和雪的能力远优于光，使雷达成为最耐候的传感器。

- 雷达还通过多普勒效应（Doppler effect）直接测量**速度**。当物体向传感器移动时，反射波被压缩（频率升高）；当远离时，反射波被拉伸（频率降低）。速度为：

$$v = \frac{\Delta f \cdot c}{2 f_0}$$

- 其中 $\Delta f$ 是频率偏移，$f_0$ 是发射频率。这给出了瞬时径向速度，无需任何跟踪或帧间计算。

- 代价是分辨率：雷达的角分辨率远不如相机或 LiDAR，难以区分靠近的物体或检测细节。它擅长在任何天气下检测远距离（200 米以上）的车辆。

- **超声波传感器**（Ultrasonic sensors）发射高频声脉冲（40-70 kHz）并测量回波返回时间。它们在极短距离（0.2-5 米）内工作，主要用于泊车辅助。其物理原理与 LiDAR 相同，只是用声音代替光，因此 $d = \frac{v_{\text{sound}} \cdot \Delta t}{2}$，其中 $v_{\text{sound}} \approx 343$ m/s。

- **IMU**（惯性测量单元，Inertial Measurement Unit）包含加速度计和陀螺仪，分别测量线性加速度和角速度。IMU 提供高频运动数据（通常 200-1000 Hz），填补了较慢传感器更新之间的间隙。它们不直接感知环境，而是跟踪机器人自身的运动，因此对于航位推算（dead-reckoning）和状态估计至关重要。

- IMU 存在**漂移**（drift）问题：小的测量误差随时间累积，导致估计位置偏离真实位置。这就是为什么 IMU 几乎总是与其他传感器（相机、GPS、LiDAR）融合使用，而不是单独使用。

- **GNSS**（全球导航卫星系统，Global Navigation Satellite Systems，包括 GPS）通过三角测量来自多颗卫星的信号，提供地球表面上的绝对位置。标准 GPS 精度为 2-5 米，不足以满足车道级驾驶。**RTK-GPS**（实时动态定位，Real-Time Kinematic）使用固定的基站来校正误差，实现厘米级精度，但需要开阔的天空视野和基站基础设施。

## 传感器标定（Sensor Calibration）

- 在传感器能够协同工作之前，它们必须被**标定**（calibrated）：每个传感器的测量必须关联到一个共同的坐标系。

- **内参标定**（Intrinsic calibration）确定传感器内部参数。对于相机，这意味着焦距、主点和畸变系数（如第 8 章所述）。对于 LiDAR，这意味着激光束之间的精确角度偏移。一种常见的方法是张氏棋盘标定法，通过从多个角度观察已知平面图案来求解内参矩阵。

- **外参标定**（Extrinsic calibration）确定两个传感器之间的刚体变换（旋转 $R$ 和平移 $\mathbf{t}$）。如果相机和 LiDAR 安装在同一辆车上，外参标定会找出将点从 LiDAR 坐标映射到相机坐标的 $4 \times 4$ 变换矩阵：

$$\mathbf{p}_{\text{cam}} = \begin{bmatrix} R & \mathbf{t} \\ \mathbf{0}^T & 1 \end{bmatrix} \mathbf{p}_{\text{lidar}}$$

- 这是齐次坐标中的仿射变换，正是我们在第 2 章（线性变换）中学过的类型。搞错这个矩阵意味着 LiDAR 点会投影到错误的像素上，整个融合流水线将崩溃。

- **时间标定**（Temporal calibration）同步传感器时钟。以 30 Hz 捕获的相机和以 10 Hz 捕获的 LiDAR 在不同时间戳上产生数据。如果汽车以 30 m/s（高速速度）行驶，10 ms 的时间误差对应 30 cm 的空间误差。硬件触发（共享时钟脉冲）或软件同步（时间戳之间的插值）至关重要。

## 传感器融合（Sensor Fusion）

- 没有一种传感器能覆盖所有条件。相机看到颜色和纹理但丢失深度。LiDAR 精确测量深度但稀疏且色盲。雷达在任何天气下都能工作但分辨率差。**传感器融合**结合它们的优势并弥补各自的弱点。

- **早期融合**（Early fusion，或数据级融合）在任何处理之前合并原始传感器数据。例如，将 LiDAR 点投影到相机图像上以创建 RGBD 表示（每个像素的颜色 + 深度），或用其投影到的相机像素的颜色为每个 LiDAR 点着色。这保留了最多信息，但需要精确的标定，并且对未对准敏感。

- **后期融合**（Late fusion，或决策级融合）独立地通过各自的检测流水线处理每个传感器，然后合并最终输出（边界框、类别标签、置信度分数）。每个传感器投票，融合模块协调分歧。这更简单、更模块化，但每个流水线无法利用其他传感器的原始数据。

- **中层融合**（Mid-level fusion）在中间特征表示上进行操作。每个传感器的原始数据被编码到学习的特征空间（使用 CNN 或 transformer），然后将特征组合起来。这是现代系统中的主导方法，因为它让网络学习从每种模态中提取什么。

![BEV 融合流水线：相机和 LiDAR 被独立编码，然后投影到共享的鸟瞰图网格中](../../images/bev_fusion_pipeline.svg)

- **BEVFusion** 是一种代表性的中层融合架构。它将相机特征和 LiDAR 特征都投影到一个共同的**鸟瞰图（BEV，bird's-eye-view）**表示中，即场景的俯视图网格。相机特征使用预测的深度分布"提升"到 3D，然后泼洒到 BEV 网格上。LiDAR 特征已经是 3D 的，直接体素化到相同的网格上。融合后的 BEV 特征然后由检测头处理。

- BEV 表示之所以强大，是因为它提供了一个统一的、具有度量尺度的坐标系，其中空间推理（距离、大小、重叠）很直接。在相机图像中，附近的自行车和远处的卡车可能占据相同数量的像素。在 BEV 中，它们的真实大小和位置是清晰的。

## 3D 目标检测（3D Object Detection）

- 感知的核心任务是在 3D 中检测物体：它们在哪里，有多大，是什么，面朝哪个方向？每个检测结果是一个**3D 边界框**，包含位置 $(x, y, z)$、尺寸 $(l, w, h)$、朝向角 $\theta$、类别标签和置信度分数。

- **基于 LiDAR 的检测**直接在点云上操作。挑战在于点云是无序的、不规则的，并且密度变化（附近的物体有数千个点，远处的物体只有几个）。回顾第 8 章，PointNet 通过共享 MLP 和置换不变的聚合（最大池化）来处理这个问题。

- **PointPillars** 通过将地平面离散化为垂直柱（"柱子"）的网格，将点云转换为结构化表示。每个柱子内的所有点由一个小的 PointNet 编码为固定大小的特征向量。结果是一个 2D 伪图像，可以由标准的 2D CNN 主干处理，然后由检测头（类似于第 8 章的 SSD 架构）处理。这既快速又有效。

- **CenterPoint** 将物体作为点而不是框来检测。它预测 BEV 中物体中心的热力图，然后在每个峰值处回归框属性（大小、高度、朝向、速度）。这是 CenterNet（第 8 章）的 3D 类比：无锚框（anchor-free），训练期间不需要 NMS，并通过跨帧关联中心点自然地扩展到跟踪。

- **仅使用相机的 3D 检测**必须从 2D 图像中推断深度，这在根本上更困难。现代方法如 **BEVDet** 和 **BEVFormer** 使用 transformer 架构将 2D 图像特征"提升"到 3D。BEVFormer 使用空间交叉注意力：BEV 查询关注投影到每个相机图像上的特定 3D 参考点，从相关位置提取特征。

- 基于 LiDAR 和基于相机的 3D 检测之间的精度差距正在迅速缩小，这得益于更好的深度估计、更大的模型和时序融合（使用多帧来累积深度线索，类似于立体匹配的工作原理，但是跨时间的）。

## 深度估计（Depth Estimation）

- 深度估计是为每个像素或点分配一个距离值的问题。

- **立体匹配**（Stereo matching）使用两个由已知基线 $b$ 分隔的相机。同一个 3D 点出现在两幅图像中略有不同的水平位置（**视差** $d$）。深度计算为（来自第 8 章）：

$$Z = \frac{f \cdot b}{d}$$

- 其中 $f$ 是焦距。挑战在于找到两幅图像之间的正确对应关系，尤其是在无纹理区域、遮挡和重复图案中。现代立体网络（例如 RAFT-Stereo）使用带有相关体的迭代精化。

- **单目深度估计**（Monocular depth estimation）从单张图像预测深度。由于这是不适定的（无限多种 3D 场景可以产生相同的图像），网络必须学习统计先验："地面是平的"，"物体随距离变小"，"纹理梯度表示后退的表面。"

- **Depth Anything**（第 8 章涵盖）通过在海量无标签数据集上进行自监督训练，然后在有标签数据上进行微调，实现了强大的单目深度。关键洞察是尺度不变损失处理固有的歧义：模型预测相对深度（排序）而不是绝对米数。

- **LiDAR-相机深度融合**将稀疏的 LiDAR 深度测量投影到相机图像上作为监督。网络学习"填补"稀疏点之间的间隙，产生结合 LiDAR 精度和相机分辨率的密集深度图。

## 占用网络（Occupancy Networks）

- 传统感知输出一个边界框列表，每个检测到的物体一个。但现实世界包含许多不适合整齐放入框中的东西：形状不规则的碎片、施工路障、悬垂的树枝、部分坍塌的墙壁。

![边界框在不规则形状上浪费空间；占用网格遵循实际几何形状](../../images/occupancy_vs_bbox.svg)

- **占用网络**将场景表示为密集的 3D 体素网格。每个体素（一个小的空间立方体，例如 0.2m × 0.2m × 0.2m）被分类为自由、占用或未知，并可选择赋予语义标签（道路、人行道、车辆、植被等）。

- 这是从以物体为中心的感知（"检测汽车"）转向以场景为中心的感知（"3D 空间的哪些部分被占用？"）。优势在于通用性：系统不需要预定义的物体类别列表就能避免与任意障碍物碰撞。

- 在架构上，占用网络接收传感器输入（相机、LiDAR 或两者），将其编码到 3D 特征体中，并预测每个体素的标签。3D 特征体通常通过将 2D 特征提升到 3D（类似于 BEV 构建但垂直扩展）来构建，并用 3D 卷积或稀疏卷积处理。

- **TPVFormer**（三视角，Tri-Perspective View）通过将 3D 体分解为三个正交平面（俯视图、前视图、侧视图）来避免全 3D 注意力的立方级成本。每个平面使用 2D 注意力，它们的特征在每个体素处组合。这让人联想到 SVD 如何将矩阵分解为更简单的因子（第 2 章）：将困难的 3D 问题分解为可管理的 2D 片段。

- 输出的体素网格直接告诉规划器哪些空间区域是安全的，哪些不是，使其成为感知和规划之间的自然接口。

## 车道检测与道路拓扑（Lane Detection and Road Topology）

- 对于在结构化道路上的车辆，理解**车道几何**至关重要。系统必须知道车道在哪里，它们如何弯曲，在哪里合并和分叉，以及车辆在哪条车道中。

- 经典方法将参数曲线拟合到检测到的车道标线上。一个常见的模型是三次多项式：

$$x(y) = a_0 + a_1 y + a_2 y^2 + a_3 y^3$$

- 其中 $y$ 是前方纵向距离，$x$ 是横向偏移。这是多项式近似（回顾第 3 章的泰勒级数），选择多项式是因为道路是平滑曲线，低次多项式可以很好地捕获。系数通过最小二乘回归在检测到的车道点上估计。

- 现代方法使用神经网络直接检测车道。**LaneNet** 将每个车道视为一个实例，并使用嵌入分支将属于同一车道的像素分组，然后进行曲线拟合。**GANet** 使用基于图的方法，将车道拓扑表示为一个有向图，其中节点是车道点，边编码连接性（哪些车道在交叉口合并、分叉或连接）。

- **道路拓扑**超越了个别车道曲线，捕获完整结构：车道如何相互连接，哪些车道允许左转，高速公路入口匝道在哪里合并。这被建模为一个有向图，其中交叉口是节点，车道段是具有属性（限速、车道类型、转弯限制）的边。

- 图结构对于路线规划至关重要：规划器不仅需要知道"车道在哪里"，还需要知道"哪些车道序列通向目的地"。

## 语义建图（Semantic Mapping）

- 感知不止于在单帧中检测物体。随着时间的推移，自主系统构建**语义地图**（semantic map）：一种持久的、结构化的环境表示，累积跨多次观测的信息。

- 最简单的情况下，语义地图是一个 2D 网格（**占用网格**，occupancy grid），其中每个单元格存储被占用的概率。当机器人移动并用其传感器扫描时，它使用贝叶斯更新来更新这些概率：

$$P(\text{occupied} \mid z_{1:t}) = \frac{P(z_t \mid \text{occupied}) \cdot P(\text{occupied} \mid z_{1:t-1})}{P(z_t)}$$

- 这是贝叶斯定理的实际应用（来自第 5 章）：每个新测量 $z_t$ 更新关于每个单元格的先验信念。**对数几率**（log-odds）表示常用于避免乘许多小概率的数值问题：

$$l_t = l_{t-1} + \log \frac{P(z_t \mid \text{occupied})}{P(z_t \mid \text{free})}$$

- 将 log-odds 相加等同于将概率相乘（回顾 $\log(ab) = \log a + \log b$），累加和自然地随着时间累积证据。

- 更丰富的地图为每个单元格分配语义标签（道路、人行道、建筑物、植被），并可以扩展到 3D。这些与占用网络密切相关，但强调持久性和时间聚合而非单帧预测。

- **SLAM**（同步定位与建图，Simultaneous Localisation and Mapping），在第 8 章中涵盖，是同时构建地图并跟踪机器人在其中的位置的算法。视觉-惯性 SLAM 融合相机和 IMU 数据；LiDAR SLAM 使用点云配准。感知流水线将检测结果和深度估计输入到 SLAM 系统中，后者维护全局地图。

- 现代方法越来越多地使用神经隐式表示（如第 8 章的 NeRF）来构建密集的、逼真的地图，可以在任意 3D 点进行查询。这些神经地图在网络权重中存储整个场景的压缩表示，从而能够实现新视图合成和详细空间查询等任务。

1. 使用投影矩阵将 3D LiDAR 点投影到 2D 相机图像上。可视化哪些点落在图像边界内。
```python
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Simulated LiDAR points in 3D (x=forward, y=left, z=up)
rng = jax.random.PRNGKey(0)
points_3d = jax.random.uniform(rng, (200, 3), minval=jnp.array([5, -10, -2]),
                                maxval=jnp.array([50, 10, 3]))

# Camera intrinsic matrix (focal length 500, image centre 320x240)
K = jnp.array([[500, 0, 320],
               [0, 500, 240],
               [0,   0,   1.0]])

# Extrinsic: LiDAR to camera (identity rotation, small translation)
R = jnp.eye(3)
t = jnp.array([0.0, 0.0, -0.5])

# Project: p_cam = K @ (R @ p_lidar + t)
p_cam = (R @ points_3d.T).T + t
p_img = (K @ p_cam.T).T
p_img = p_img[:, :2] / p_img[:, 2:3]  # divide by Z

# Filter points in front of camera and within image
mask = (p_cam[:, 2] > 0) & (p_img[:, 0] > 0) & (p_img[:, 0] < 640) & \
       (p_img[:, 1] > 0) & (p_img[:, 1] < 480)
depth = p_cam[mask, 2]

plt.figure(figsize=(8, 5))
plt.scatter(p_img[mask, 0], p_img[mask, 1], c=depth, cmap="viridis", s=5)
plt.colorbar(label="Depth (m)")
plt.xlim(0, 640); plt.ylim(480, 0)
plt.title("LiDAR points projected onto camera image")
plt.xlabel("u (pixels)"); plt.ylabel("v (pixels)")
plt.show()
```

2. 使用贝叶斯 log-odds 更新构建一个简单的 2D 占用网格。模拟一个距离传感器扫描环境并观察地图如何涌现。
```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Grid setup: 50x50 cells, each 0.2m
grid_size = 50
log_odds = jnp.zeros((grid_size, grid_size))

# Sensor model: log-odds update values
l_occ = 0.85   # confidence that a hit means occupied
l_free = -0.4  # confidence that a pass-through means free

# Simulated obstacle: a wall from (5,20) to (5,30) in grid coords
wall_y = jnp.arange(20, 30)

# Robot at (25, 25), scanning outward
robot = jnp.array([25, 25])

for angle_deg in range(0, 360, 5):
    angle = jnp.radians(angle_deg)
    direction = jnp.array([jnp.cos(angle), jnp.sin(angle)])

    for step in range(1, 25):
        cell = (robot + direction * step).astype(int)
        r, c = int(cell[0]), int(cell[1])
        if r < 0 or r >= grid_size or c < 0 or c >= grid_size:
            break

        # Check if this cell is the wall
        is_wall = (r == 5) and (c >= 20) and (c < 30)
        if is_wall:
            log_odds = log_odds.at[r, c].add(l_occ)
            break
        else:
            log_odds = log_odds.at[r, c].add(l_free)

# Convert log-odds to probability
prob = 1.0 / (1.0 + jnp.exp(-log_odds))

plt.figure(figsize=(6, 6))
plt.imshow(prob.T, origin="lower", cmap="RdYlGn_r", vmin=0, vmax=1)
plt.colorbar(label="P(occupied)")
plt.plot(25, 25, "b*", markersize=10, label="Robot")
plt.legend()
plt.title("2D Occupancy Grid from Bayesian Updates")
plt.show()
```

3. 使用视差从立体图像对计算深度。模拟两个相机视角的 3D 点，计算视差，并恢复深度。
```python
import jax
import jax.numpy as jnp

# Camera parameters
f = 500.0     # focal length in pixels
b = 0.12      # baseline in metres (12 cm)

# 3D points at known depths
depths_true = jnp.array([5.0, 10.0, 20.0, 50.0, 100.0])

# Disparity = f * b / Z
disparities = f * b / depths_true

# Recover depth from disparity
depths_recovered = f * b / disparities

for z, d, z_r in zip(depths_true, disparities, depths_recovered):
    print(f"True depth: {z:6.1f}m  Disparity: {d:6.2f}px  Recovered: {z_r:6.1f}m")

# Notice: disparity is inversely proportional to depth
# Close objects have large disparity, far objects have tiny disparity
# This is why stereo is most accurate at short range
```
