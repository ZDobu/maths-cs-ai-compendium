# 自动驾驶汽车（Self-Driving Cars）

*自动驾驶汽车是商业上最先进的自主系统，将感知、预测、规划和控制集成到一辆车中。本文件涵盖自动驾驶软件栈、高清地图（HD maps）、运动预测、规划、端到端驾驶、仿真、安全标准和自主级别*

- 自动驾驶汽车可以说是正在尝试大规模解决的最困难的机器人学问题。与在受控环境中工作的工厂机器人不同，自动驾驶汽车必须处理开放世界：不可预测的人类驾驶员、乱穿马路的行人、一夜之间出现的施工区域，以及每分钟都在变化的天气。

- 风险也格外高。自动驾驶汽车在脆弱的道路使用者中以高速公路速度运行。对于安全关键的故障，误差容忍度接近于零。

## 自动驾驶软件栈（The Autonomous Driving Stack）

- 经典的自动驾驶架构是一个**模块化流水线**，有四个阶段，每个阶段馈入下一个：

$$\text{感知（Perception）} \to \text{预测（Prediction）} \to \text{规划（Planning）} \to \text{控制（Control）}$$

![自动驾驶软件栈：传感器馈入感知，感知馈入预测、规划，最后是控制](../../images/autonomous_driving_stack.svg)

- **感知**（本章文件 1 涵盖）将原始传感器数据处理为结构化的场景表示：具有 3D 位置、速度和类别标签的检测到的物体；车道标线；交通灯；可驾驶表面边界。

- **预测**预测其他交通参与者（车辆、行人、自行车）在未来如何移动。给定场景的当前状态，预测模块为每个参与者输出一定时间跨度（通常为未来 3-8 秒）内的轨迹。

- **规划**决定本车（ego vehicle）应该做什么：走哪条路径，何时换道，何时让行，何时加速或刹车。它接收预测的场景并为本车生成一条安全、舒适且朝目的地前进的轨迹。

- **控制**将规划轨迹转换为执行器命令：转向角度、油门和刹车。这是最低层，将抽象轨迹转化为物理运动。

- 模块化设计具有明确的工程优势：每个模块可以独立开发、测试和改进。但它也有弱点：错误会向下游传播（一次漏检对规划器是不可见的），并且信息在每个接口处都会丢失（规划器看到的是边界框，而不是产生它们的丰富传感器数据）。

## 高清地图（HD Maps）

- **高清（HD）地图**是详细的、厘米级精度的数字地图，编码道路结构：车道边界、车道连接性（在交叉口哪条车道连接哪条）、交通标志位置、限速、人行横道位置和路面高程。

- HD 地图为驾驶任务提供了强大的先验。感知模块不需要每帧都从头发现车道边界；它只需要在地图中定位车辆并验证现实是否与存储的结构匹配。这大大简化了规划。

- 构建 HD 地图需要配备高端 LiDAR、相机和 RTK-GPS 的专用测绘车辆。地图必须随着道路变化而维护和更新。这很昂贵，并且不容易扩展到地球上的每条道路。

- **无图驾驶**（Mapless driving，也称为"在线建图"）旨在消除对预构建 HD 地图的依赖。取而代之，车辆实时从其传感器构建本地地图。像 **MapTR** 和 **MapTRv2** 这样的模型使用 transformer 架构直接从相机图像预测矢量化地图元素（车道中心线、道路边界、人行横道），输出作为有序点序列的多段线。

- 无图方法以地图精度换取可扩展性：汽车能开到的任何道路，它都能建图。但它要求感知系统足够鲁棒，能够实时检测所有相关的道路结构，包括在复杂交叉口、高速公路匝道和施工区域。

- 在实践中，许多系统使用混合方法：带有粗略道路拓扑的轻量级地图（来自现有地图提供商），由车辆传感器实时丰富。

## 运动预测（Motion Prediction）

- 预测其他道路使用者将去哪里是自动驾驶中最困难的子问题之一。人类是不可预测的，意图是隐藏的，可能未来的空间迅速分岔。

- 预测模型的输入是**场景上下文**（scene context）：所有检测到的参与者在最近一段时间（通常 1-2 秒的历史）内的位置和速度，加上静态上下文（车道几何、交通信号、道路边界）。

- 输出是每个参与者的一组**预测轨迹**，通常涵盖未来 3-8 秒。由于未来是不确定的，好的预测模型输出多个可能轨迹及其相关概率，而不是单一的点估计。

- **轨迹预测**作为回归问题：预测每个参与者在未来离散时间步的 $(x, y)$ 坐标。损失通常是 $K$ 条预测轨迹上的最小平均位移误差（minADE）：

$$\text{minADE}_K = \min_{k \in \{1, \ldots, K\}} \frac{1}{T} \sum_{t=1}^{T} \| \hat{\mathbf{p}}_t^{(k)} - \mathbf{p}_t \|_2$$

- 这是一个"$K$ 中最佳"度量：如果模型的任何 $K$ 个预测中有一个接近真实值，模型就得到肯定。这鼓励多样化、多模态的预测。

- **社会力**（Social forces）将行人行为建模为一个动力学系统，每个人经历吸引力（朝向其目标）和排斥力（远离其他行人和障碍物）。人 $i$ 的加速度为：

$$\mathbf{a}_i = \frac{\mathbf{v}_i^{\text{desired}} - \mathbf{v}_i}{\tau} + \sum_{j \neq i} \mathbf{f}_{ij}^{\text{repulsive}} + \sum_{\text{walls}} \mathbf{f}_{\text{wall}}$$

- 这是一个微分方程组，类似于本章文件 2 中的机器人动力学方程。模型很优雅，但依赖手工调参的力参数，难以处理复杂的多智能体交互。

- **图神经网络（GNN）**用于预测，将场景建模为图：每个参与者是一个节点，边表示空间关系（邻近性、共享车道）。节点之间的消息传递捕获交互："这辆车正在让那个行人"或"这两辆车正在汇入同一条车道"。

- 现代预测架构（例如 **MTR**、**QCNet**）使用基于 transformer 的模型，共同推理智能体历史、地图上下文和智能体-智能体交互。智能体通过交叉注意力关注相关的地图特征（其当前车道、即将到来的交叉口）和其他智能体（前方车辆、人行横道处的行人）。输出是通过自回归或混合模型生成的一组轨迹假设。

- **目标条件预测**（Goal-conditioned prediction）首先预测一个智能体可能去哪里（一组候选目标点，如车道终点或交叉口出口），然后预测到达每个目标的轨迹。这将问题分解为"去哪里"（离散的、可管理的）和"如何到达"（给定目标的连续路径），使多模态预测问题更加可处理。

## 规划（Planning）

- 给定预测的场景，规划器必须为本车生成一条轨迹。这是一个约束优化问题：找到一条安全、舒适、高效且合法的轨迹。

- **基于规则的规划器**将驾驶行为编码为一组 if-then 规则："如果行人在人行横道上，让行"，"如果与前车距离小于 2 秒，不要换道"，"如果接近红灯，减速停在停止线处。"这些规则可解释、可审计，但对于复杂场景（数千条规则、许多边缘情况、规则之间的交互）会变得笨拙。

- **基于优化的规划器**将驾驶公式化为轨迹优化。本车轨迹被参数化（例如，作为未来时间步的 $(x, y, \theta, v)$ 状态序列），并最小化一个目标函数：

$$\min_{\boldsymbol{\xi}} \underbrace{w_1 \cdot J_{\text{progress}}(\boldsymbol{\xi})}_{\text{到达目的地}} + \underbrace{w_2 \cdot J_{\text{comfort}}(\boldsymbol{\xi})}_{\text{平稳行驶}} + \underbrace{w_3 \cdot J_{\text{safety}}(\boldsymbol{\xi})}_{\text{避免碰撞}}$$

$$\text{约束条件：} \text{运动学约束、限速、车道边界}$$

- 进度项惩罚偏离期望路线的程度。舒适项惩罚高横向加速度、急动度（加速度的导数）和突然转向，因为乘客能感受到这些。安全项惩罚与其他智能体的接近程度，使用预测轨迹评估碰撞风险。

- 这是约束优化（第 3 章）：在不等式约束下最小化成本函数。权重 $w_1, w_2, w_3$ 在竞争目标之间进行权衡（激进的驾驶更快但不太舒适且不太安全）。

- **基于学习的规划器**使用在人类驾驶数据上训练的神经网络来生成轨迹。模型观察场景并直接输出规划的轨迹，从专家人类驾驶的示例中隐式学习复杂的权衡。

- 优势在于人类驾驶行为被整体捕获，包括微妙的、难以形式化的方面：多 aggressive 地汇入、何时在交叉口微微前进、给自行车骑手留多少空间。劣势是与模仿学习（文件 2）相同的分布偏移问题：模型在训练数据未充分表示的情况下可能表现出不可预测的行为。

## 端到端驾驶（End-to-End Driving）

- **端到端驾驶**去掉了模块边界。单个神经网络接收原始传感器输入（相机图像、LiDAR 点云）并直接输出驾驶命令（转向、油门、刹车）或规划的轨迹。没有独立的感知、预测或规划模块。

- 其吸引力在于整个系统对最终任务（安全驾驶）进行联合优化，因此在模块边界不会丢失信息。感知模块学习提取规划器所需的确切特征，而不是可能无法捕获任务相关细节的通用物体检测。

- **UniAD**（统一自动驾驶，Unified Autonomous Driving）是一种里程碑式的端到端架构。它将多相机图像通过 BEV 编码器处理，然后应用级联的基于 transformer 的模块：跟踪、在线建图、运动预测、占用预测和规划。虽然它有内部模块，但它们都是可微分的，并且端到端联合训练，规划损失通过网络反传回来。

- UniAD 中的规划模块通过关注预测的 BEV 特征、预测的智能体轨迹和预测的占用来生成未来本车航点。这是多元链式法则（第 3 章）的实际应用：梯度从规划损失一路流回图像编码器，告诉感知特征如何对规划更有用。

- 更近期的端到端方法使用 VLA 风格的架构（本章文件 3）。像 **DriveVLM** 这样的模型接收相机图像和导航指令（或路线），并使用 VLM 主干产生驾驶动作。这为驾驶栈直接带来了大规模预训练的好处（视觉理解、推理）。

- 端到端驾驶的张力在于**可解释性**（interpretability）。一个模块化系统可以报告"我检测到一个行人在 (x, y) 处，并预测他们会横穿"—— 故障模式是可诊断的。一个端到端系统是一个产生转向角的黑箱。当它失败时，诊断原因是困难的，这对安全认证是一个严重关切。

## 用于驾驶的世界模型（World Models for Driving）

- **世界模型**学习在给定当前状态和本车动作的情况下预测驾驶场景的未来状态：$p(s_{t+1} \mid s_t, a_t)$（如第 10 章介绍的）。在驾驶中，这意味着生成逼真的未来帧或 BEV 布局："如果我加速并向左转，场景将在 3 秒后看起来像这样。"

- 世界模型为自动驾驶提供了两种强大的能力：

    - **基于想象的规划**（Imagination-based planning）：规划器不提交一个动作然后看会发生什么，而是可以"想象"多条候选轨迹，通过世界模型将它们展开，评估每条轨迹的安全性和舒适性，并选择最佳的一条。这是应用于驾驶的基于模型的 RL（本章文件 2 涵盖）。

    - **学习到的仿真**（Learned simulation）：在真实驾驶数据上训练的世界模型实际上是一个数据驱动的仿真器。它生成逼真的场景（包括罕见的边缘情况），无需手工构建仿真器的手动工作。至关重要的是，它捕获了真实驾驶的统计模式：其他驾驶员实际如何行为，光照如何变化，雨如何影响能见度。

- **GAIA-1**（Wayve）是一个用于驾驶的生成式世界模型。给定过去的相机帧和本车动作序列，它自回归地生成未来的视频帧。它使用以动作输入为条件的视频扩散架构。模型学会生成合理的未来：遵守交通规则的车辆、在人行道上行走的行人，以及正确切换的交通灯，所有这些都从训练数据中涌现，而非通过编程的规则。

- **DriveDreamer** 和 **GenAD** 采用了类似的方法，但在 BEV 空间而非像素空间中操作。预测未来的 BEV 布局比生成完整的视频帧更紧凑（类似于机器人学中的 DreamerV3 在潜在空间而非像素空间中预测，如文件 2 中讨论的）。BEV 世界模型预测所有智能体将在哪里、道路结构将是什么样子、以及自由空间在哪里，规划器直接使用这些信息。

- **神经闭环仿真** 使用世界模型替代手工构建的仿真器进行测试。以真实驾驶日志为起点，世界模型生成如果本车采取了不同动作时会发生什么。这实现了反事实评估："如果我晚 0.5 秒刹车会怎样？"而无需物理上重现该场景。

- 与 **JEPA** 框架（第 10 章）的联系在这里是自然的。驾驶世界模型不需要预测像素完美的未来（每个像素的精确 RGB 值）。它们需要预测对规划有意义的方面：智能体在哪里，它们移动有多快，自由空间在哪里。嵌入空间预测（JEPA 风格）捕获这些语义上有意义的属性，而不会将容量浪费在无关紧要的视觉细节上，如精确的云纹理。

- 主要挑战是**长时域保真度**（long-horizon fidelity）。世界模型随时间累积误差：第 2 帧中的一个小错误会偏移所有后续帧。对于驾驶，3 秒的预测时域对战术决策（我现在应该汇入吗？）是有用的，但 30 秒的时域（路线规划等战略决策所需）仍然不可靠。当前工作通过重新锚定（定期用真实观测重置模型）和不确定性估计（标记预测何时变得不可靠）来缓解这个问题。

## 仿真（Simulation）

- 通过在真实道路上驾驶来测试自动驾驶汽车是必要但不充分的。危险的场景（接近碰撞、边缘情况）是罕见的，因此按行驶里程测试是低效的。一辆汽车需要驾驶数亿英里才能统计上证明安全性，这是不可行的。

- **仿真**提供无限、可控且安全的测试。在现实世界中罕见的场景（孩子跑到马路上、轮胎爆裂、突然的障碍物）可以在仿真中测试数百万次。

- **CARLA** 是一个基于 Unreal Engine 构建的开源驾驶仿真器。它提供逼真的城市环境、动态天气、交通参与者和传感器仿真（相机、LiDAR、雷达）。研究人员使用 CARLA 训练基于 RL 的驾驶智能体和评估感知算法。

- **nuPlan**（Motional）是一个闭环规划基准。与开环评估（回放记录的数据，将规划器的输出与人类驾驶员的实际轨迹进行比较）不同，闭环评估让规划器的决策影响仿真：如果规划器决定换道，仿真会相应地演化。这测试的是反应性行为，而不仅仅是轨迹相似性。

![开环回放日志而不交互；闭环让模型的动作改变仿真状态](../../images/open_vs_closed_loop.svg)

- **开环**和**闭环**评估之间的区别至关重要：

    - 开环：回放记录的场景，计算模型输出与人类驾驶员动作的相似度。这设置简单但具有误导性：始终预测"直行"的模型在高速公路上可能误差很低，但在第一个转弯处就会撞车。

    - 闭环：模型的动作改变仿真状态，仿真相应地演化。这测试模型从自身错误中恢复并对动态情况作出反应的能力。它昂贵得多，但意义也大得多。

- **场景生成**创建对系统施压的测试用例。对抗性场景（一辆车突然刹车、一个行人藏在停放的汽车后面）通过优化自动驾驶系统表现最差的情况来生成。这与 ML 中的对抗训练（第 6 章）相关：找到最大化损失的输入。

## 安全（Safety）

- 自动驾驶中的安全受工程标准规范，而不仅仅是 ML 指标。

- **ISO 26262**（功能安全，Functional Safety）是用于安全关键电子系统的汽车标准。它根据潜在危害的严重性、暴露度和可控性定义了**汽车安全完整性等级（ASIL）**，从 A（最低）到 D（最高）。自动驾驶系统的感知和规划组件通常是 ASIL-D 的最高级别，要求进行广泛的验证、冗余和故障安全设计。

- **SOTIF**（预期功能的安全性，Safety of the Intended Functionality，ISO 21448）解决了一类不同的危害：不是硬件故障（ISO 26262 涵盖的），而是系统按设计工作但仍产生不安全结果的情况。一个将白色卡车误分类为天空的感知模型（真实事件）是一个 SOTIF 问题：硬件工作正常，但算法的局限性导致了危害。

- **运行设计域**（Operational Design Domain, ODD）定义了自动驾驶系统设计为可以运行的条件：特定的地理区域、道路类型（仅高速、城市、两者）、天气条件（无大雪）、速度范围和一天中的时间。在 ODD 之外运行是不允许的：如果系统不能处理雪地，它就不能在雪地中驾驶。

- **故障安全**（Fail-safe）vs **故障可运行**（Fail-operational）设计：
    - 故障安全：当检测到故障时，系统转换到安全状态（例如，靠边停车）。这是最低要求。
    - 故障可运行：尽管存在故障，系统仍继续安全运行，使用冗余组件。具有冗余转向、制动和计算的自动驾驶汽车可以在单个组件故障下生存，并仍然驾驶到安全位置。

- **冗余**是根本性的。关键感知传感器被复制：覆盖重叠视场的多个相机，LiDAR 和雷达都提供独立的深度测量，双计算平台运行相同的软件。如果任何单个组件失败，其他组件提供足够的信息以安全驾驶。

## 自主级别（Levels of Autonomy）

![SAE 自主级别从 L0（无自动化）到 L5（完全自动化），显示责任从人类转移到系统的位置](../../images/sae_autonomy_levels.svg)

- **SAE J3016** 标准定义了六个驾驶自动化级别，从 0（无自动化）到 5（完全自动化）：

    - **级别 0（无自动化）**：人类完成一切。系统可能提供警告（车道偏离警报）但不控制车辆。

    - **级别 1（驾驶员辅助）**：系统控制转向或速度，但不是两者都控制。自适应巡航控制（保持速度和跟车距离）或车道保持辅助（使汽车在车道中居中）是级别 1。

    - **级别 2（部分自动化）**：系统同时控制转向和速度，但人类必须始终监视并随时准备接管。Tesla Autopilot、GM Super Cruise 和大多数当前的"自动驾驶"功能是级别 2。人类仍然是负责任的驾驶员。

    - **级别 3（有条件自动化）**：系统在特定条件（ODD）下驾驶并监视环境。人类可以脱离，但必须在系统请求时准备接管（有时间缓冲，通常 10+ 秒）。Mercedes Drive Pilot（在特定高速公路上，60 km/h 以下）是第一个认证的级别 3 系统。

    - **级别 4（高度自动化）**：系统驾驶并处理其 ODD 内的所有情况，无需人类干预。如果它遇到 ODD 外的情况，它可以安全地自己停下来。Waymo 的 robotaxi 服务在特定地理区域以级别 4 运行。

    - **级别 5（完全自动化）**：系统在人类能驾驶的所有地方、所有条件下驾驶。不需要方向盘或踏板。这尚未存在。

- 关键区别是**谁对安全负责**。在级别 0-2，人类负责。在级别 3-5，系统负责（在其 ODD 内）。这具有深远的法律、保险和伦理意义。

- 当前的行业状态是级别 2（广泛部署）、级别 3（开始部署）和级别 4（有限地理部署）的混合。级别 5 仍然是一个长期研究目标。

1. 实现一个简单的轨迹优化规划器。给定起始位置、目标和障碍物，使用梯度下降找到最平滑的无碰撞路径。
```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Trajectory: N waypoints, each (x, y)
N = 20
start = jnp.array([0.0, 0.0])
goal = jnp.array([10.0, 0.0])
obstacle = jnp.array([5.0, 0.0])
obs_radius = 1.5

# Initialise: straight line from start to goal
waypoints_init = jnp.linspace(start, goal, N)

def cost(waypoints):
    wp = jnp.concatenate([start[None], waypoints, goal[None]], axis=0)

    # Smoothness: penalise acceleration (second differences)
    accel = wp[2:] - 2 * wp[1:-1] + wp[:-2]
    smooth_cost = jnp.sum(accel ** 2)

    # Obstacle avoidance: penalise proximity
    dists = jnp.linalg.norm(wp - obstacle, axis=1)
    collision_cost = jnp.sum(jnp.maximum(0, obs_radius + 0.5 - dists) ** 2)

    return 10 * smooth_cost + 100 * collision_cost

grad_cost = jax.grad(cost)

# Optimise the interior waypoints
waypoints = waypoints_init[1:-1]
lr = 0.01
for _ in range(500):
    g = grad_cost(waypoints)
    waypoints = waypoints - lr * g

# Plot
full_path = jnp.concatenate([start[None], waypoints, goal[None]], axis=0)
theta = jnp.linspace(0, 2 * jnp.pi, 100)

plt.figure(figsize=(10, 4))
plt.plot(full_path[:, 0], full_path[:, 1], "b.-", label="Optimised path")
plt.plot(waypoints_init[:, 0], waypoints_init[:, 1], "r--", alpha=0.5, label="Initial (straight)")
plt.fill(obstacle[0] + obs_radius * jnp.cos(theta),
         obstacle[1] + obs_radius * jnp.sin(theta), alpha=0.3, color="red", label="Obstacle")
plt.plot(*start, "go", markersize=10); plt.plot(*goal, "g*", markersize=15)
plt.legend(); plt.axis("equal"); plt.grid(True)
plt.title("Trajectory Optimisation: Smooth Collision-Free Path")
plt.show()
```

2. 模拟一个恒定速度运动预测模型，并与转弯车辆的真实轨迹进行比较。
```python
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Ground truth: vehicle turning right
dt = 0.1
T = 40  # 4 seconds
v = 10.0  # m/s
omega = 0.3  # rad/s (turning rate)

# True trajectory (constant turn rate)
t = jnp.arange(T) * dt
theta = omega * t
gt_x = (v / omega) * jnp.sin(theta)
gt_y = (v / omega) * (1 - jnp.cos(theta))

# Constant velocity prediction from t=0
# Assumes the car continues straight at its current heading
obs_steps = 10  # observe first 1 second
vx0 = v * jnp.cos(theta[obs_steps - 1])
vy0 = v * jnp.sin(theta[obs_steps - 1])
pred_t = jnp.arange(T - obs_steps) * dt
pred_x = gt_x[obs_steps - 1] + vx0 * pred_t
pred_y = gt_y[obs_steps - 1] + vy0 * pred_t

plt.figure(figsize=(8, 6))
plt.plot(gt_x[:obs_steps], gt_y[:obs_steps], "ko-", label="Observed")
plt.plot(gt_x[obs_steps:], gt_y[obs_steps:], "g-", linewidth=2, label="True future")
plt.plot(pred_x, pred_y, "r--", linewidth=2, label="Constant velocity prediction")
plt.legend(); plt.axis("equal"); plt.grid(True)
plt.xlabel("x (m)"); plt.ylabel("y (m)")
plt.title("Constant Velocity Prediction vs Turning Vehicle")
plt.show()
```

3. 实现一个简单的基于规则的规划器，根据检测到的障碍物决定车道保持还是停车。
```python
import jax.numpy as jnp

def rule_based_planner(ego_speed, obstacles, speed_limit=13.9):
    """
    Simple rule-based planner.
    ego_speed: current speed (m/s)
    obstacles: list of (distance, speed) tuples for vehicles ahead
    speed_limit: max allowed speed (m/s), default ~50 km/h

    Returns: (target_speed, action_label)
    """
    min_following_distance = 2.0 * ego_speed  # 2-second rule
    emergency_distance = 5.0  # metres

    if not obstacles:
        return speed_limit, "cruise"

    # Find closest obstacle ahead
    closest_dist, closest_speed = min(obstacles, key=lambda o: o[0])

    if closest_dist < emergency_distance:
        return 0.0, "EMERGENCY STOP"
    elif closest_dist < min_following_distance:
        # Match speed of vehicle ahead
        target = min(closest_speed, speed_limit)
        return target, "following"
    else:
        return speed_limit, "cruise"

# Test scenarios
scenarios = [
    (13.9, [], "Empty road"),
    (13.9, [(30.0, 10.0)], "Slower car ahead"),
    (13.9, [(3.0, 0.0)], "Stopped car very close"),
    (13.9, [(50.0, 13.9)], "Car ahead at same speed"),
]

for speed, obs, desc in scenarios:
    target, action = rule_based_planner(speed, obs)
    print(f"{desc:30s}  →  {action:15s} target_speed={target:.1f} m/s ({target*3.6:.0f} km/h)")
```
