# 高级文本生成（Advanced Text Generation）

*高级文本生成超越了普通的自回归解码，以提升质量、可控性和速度。本章涵盖文本扩散模型（D3PM、MDLM）、OCR、用于对齐的RLHF和DPO、长上下文方法（RoPE缩放、环注意力）、检索增强生成，以及用于更快推理的推测解码。*

- 标准的自回归生成（第04章）一次一个token、从左到右地生成文本。这种方法简单有效，但本质上是串行的，不允许全局规划，并且对输出的控制有限。本章涵盖超越普通自回归解码的方法：文本扩散模型、光学字符识别（OCR）、通过人类反馈进行可控生成、处理长上下文、检索增强生成，以及用于更快推理的推测解码。

- **文本扩散模型（Text diffusion models）**将扩散框架（第08章中用于图像的部分）应用于离散文本。核心挑战在于文本是离散的：不能像向像素加噪声那样向token添加连续的高斯噪声。有几种方法来解决这个问题。

- **D3PM**（离散去噪扩散概率模型，Discrete Denoising Diffusion Probabilistic Models，Austin等人，2021）使用转移矩阵直接在离散token上定义前向破坏过程。在每个前向步骤中，token有一定的概率被另一个token替换（均匀噪声）、被掩码（吸收态）或保持不变。反向过程学习去噪，从被破坏的token预测干净的token。步骤$t$的转移矩阵$Q_t$控制破坏过程：

$$q(x_t \mid x_{t-1}) = \text{Cat}(x_t ; \, x_{t-1} Q_t)$$

- 其中$\text{Cat}$表示分类分布（categorical distribution），$x$是独热向量。多步前向过程$q(x_t \mid x_0)$有闭合形式：$q(x_t \mid x_0) = \text{Cat}(x_t ; \, x_0 \bar{Q}_t)$，其中$\bar{Q}_t = Q_1 Q_2 \cdots Q_t$是直到步骤$t$的所有转移矩阵的乘积。训练最小化一个跨时间步分解的变分下界（ELBO），类似于连续情况（第08章）：

$$\mathcal{L}_{\text{D3PM}} = D_{\text{KL}}(q(x_T \mid x_0) \| p(x_T)) + \sum_{t=2}^{T} D_{\text{KL}}(q(x_{t-1} \mid x_t, x_0) \| p_\theta(x_{t-1} \mid x_t)) - \log p_\theta(x_0 \mid x_1)$$

- 第一项确保完全破坏的分布与先验（均匀或全掩码）匹配。KL项之和训练模型逆转每个破坏步骤：真实的逆向后验$q(x_{t-1} \mid x_t, x_0)$可以通过贝叶斯规则和已知的转移矩阵以闭合形式计算，模型$p_\theta(x_{t-1} \mid x_t)$被训练来匹配它。

- 由于两者都是分类分布，KL散度是词表条目上的简单求和。最后一项衡量从最轻破坏状态重建的质量。

- **MDLM**（掩码扩散语言模型，Masked Diffusion Language Models，Sahoo等人，2024）通过将掩码作为唯一的破坏操作来简化D3PM：前向过程逐步将token替换为[MASK] token，反向过程预测原始token。这将文本扩散与掩码语言建模（BERT，第04章）联系起来，扩散时间步控制着有多少比例的token被掩码。在$t = 0$时，文本完全干净；在$t = T$时，文本完全被掩码。

- **连续文本扩散**通过在连续嵌入空间中操作来绕过离散问题。Token首先映射到其嵌入向量（第06章），在这个连续空间中添加噪声，一个去噪模型（通常是Transformer）学习逆转这一过程。在生成时，模型产生连续向量，通过找到最近的嵌入将其映射回离散token。挑战在于连续空间中的小误差可能映射到完全错误的token，因此需要仔细进行舍入和截断。

- 文本扩散的吸引力在于它通过迭代细化同时生成所有token，而不是从左到右。这允许全局连贯性和轻松的中文填空（生成段落中间的缺失文本），但当前的文本扩散模型在长文本的生成质量上仍落后于自回归模型。

- **文本OCR**（光学字符识别，Optical Character Recognition）是从图像中提取文本的任务。虽然传统上不被归类于语言生成，但现代OCR系统已与NLP深度整合，并越来越多地使用语言模型组件。

- **场景文本检测（Scene text detection）**定位自然图像中的文本区域（路牌、产品标签、车牌）。这在技术上具有挑战性，因为真实场景中的文本出现在任意的角度、尺寸、字体和杂乱的背景中。检测方法通常使用CNN或Transformer骨干网络生成文本区域周围的边界框或分割掩码。

- **CRNN**（卷积循环神经网络，Convolutional Recurrent Neural Network，Shi等人，2017）是一个经典的文本识别架构。CNN从文本图像中提取视觉特征，特征图被切分为一系列列（每个水平位置一列），一个双向LSTM读取这个序列以建模上下文。输出使用**CTC**（连接时序分类，Connectionist Temporal Classification）进行解码，它处理输入列与输出字符之间的对齐，而不需要显式分割。

- CTC解决的基本问题是：模型产生$T$个输出分布（每个输入列一个），但目标文本有$L \leq T$个字符。

- 我们不知道哪些列对应哪些字符。CTC引入一个**空白token（blank token）**$\epsilon$，并定义一个多对一映射$\mathcal{B}$，将重复字符折叠并删除空白：$\mathcal{B}(\text{"HH-ee-ll-ll-oo"}) = \text{"Hello"}$（其中"-"是空白）。

- 目标序列$y$的概率是所有坍缩为$y$的输入对齐路径的总和：

$$P(y \mid x) = \sum_{\pi \in \mathcal{B}^{-1}(y)} \prod_{t=1}^{T} P(\pi_t \mid x)$$

- 其中$\pi$是长度为$T$的对齐路径（每个列一个标签，包括空白）。朴素地遍历所有路径是指数级的，但**前向算法（forward algorithm）**（第05章HMM）使用动态规划以$O(T \cdot L)$时间高效计算此总和。

- 空白token是必不可少的：没有它，"Hello"中像"ll"这样的重复字符将与单个"l"不可区分。训练最大化$\log P(y \mid x)$，在推理时，通过对CTC输出进行束搜索或贪心解码找到最佳路径。

- **文档OCR**处理结构化文档（发票、表单、科学论文），除了识别字符外，还必须理解布局。像LayoutLM这样的现代系统将文本识别与空间位置特征相结合：每个token同时获得其文本嵌入和一个编码其在页面上$(x, y)$坐标的位置嵌入。这使模型能够理解出现在"Total:"下方的数字就是总金额。

![CRNN OCR流水线](../../images/crnn_ocr_pipeline.svg)

- **视觉-语言OCR**模型如TrOCR将文本识别视为图像到文本的生成：一个视觉Transformer（ViT）编码器处理图像，一个语言模型解码器逐字符生成文本。这利用了预训练的视觉和语言模型的力量，无需手工设计特征工程即可处理多样化的文字、字体和布局。

- **可控生成（Controllable generation）**是指引导语言模型生成具有期望属性的输出的挑战：特定的风格、主题、情感、安全级别或事实准确性。模型应该在保持流畅和连贯的同时遵循指令。

- **无分类器引导（Classifier-Free Guidance，CFG）**用于文本，改编自图像生成中的技术。在训练期间，条件信号（例如提示）在部分时间内被随机丢弃，在一个模型中同时训练条件模型和无条件模型。在推理时，输出logits被插值：

$$\text{logits}_{\text{guided}} = (1 + w) \cdot \text{logits}_{\text{conditional}} - w \cdot \text{logits}_{\text{unconditional}}$$

- 其中$w > 0$放大条件的影响。更高的$w$使输出更强烈地遵循提示，但会降低多样性。

- **RLHF**（基于人类反馈的强化学习，Reinforcement Learning from Human Feedback，Ouyang等人，2022）是使语言模型与人类偏好对齐的主导方法。该过程有三个阶段：

- 第一，**监督微调（Supervised Fine-Tuning，SFT）**：在高质量的、人工撰写的对提示的回复数据集上微调基础语言模型。

- 第二，**奖励模型训练（reward model training）**：收集人类比较数据（给定提示$x$和两个回复$y_1, y_2$，哪个更好？）并训练一个奖励模型$r_\phi(x, y)$来预测人类偏好。奖励模型以成对排序损失进行训练：

$$\mathcal{L}_{\text{RM}} = -\log \sigma(r_\phi(x, y_w) - r_\phi(x, y_l))$$

- 其中$y_w$是被偏好的回复，$y_l$是不被偏好的回复。

- 第三，**RL微调**：优化语言模型以最大化奖励，同时保持在SFT模型附近（防止模式崩溃）。这使用PPO（近端策略优化，Proximal Policy Optimisation，来自第06章）和KL惩罚：

$$\mathcal{L}_{\text{RL}} = -\mathbb{E}\left[r_\phi(x, y) - \beta \, D_{\text{KL}}(\pi_\theta \| \pi_{\text{SFT}})\right]$$

- KL项防止模型偏离基础模型太远并利用奖励模型的漏洞（"奖励欺骗 reward hacking"）。

![RLHF流水线](../../images/rlhf_pipeline.svg)

- **DPO**（直接偏好优化，Direct Preference Optimisation，Rafailov等人，2023）通过完全消除奖励模型来简化RLHF。关键的数学洞察在于，上述KL约束的RL目标具有闭合形式的最优策略：

$$\pi^\ast(y \mid x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y \mid x) \exp\!\left(\frac{r(x, y)}{\beta}\right)$$

- 其中$Z(x)$是归一化配分函数。将此项重新排列得到奖励表达式$r(x, y) = \beta \log \frac{\pi^\ast(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)$。将此隐式奖励代入Bradley-Terry偏好模型$P(y_w \succ y_l) = \sigma(r(x, y_w) - r(x, y_l))$中，不可解的$Z(x)$项会相互抵消，直接得到DPO损失：

$$\mathcal{L}_{\text{DPO}} = -\log \sigma\!\left(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\right)$$

- 这在数学上等价于RLHF，但将奖励模型和RL训练合并为单个监督步骤。

- Sigmoid内部的表达式可以解读为："相对于参考模型，增加被偏好回复的相对概率，并减少不被偏好回复的相对概率。"

- $\beta$参数控制策略可以偏离参考模型的程度。在实践中，DPO更易于实现（只需计算两个回复在当前模型和参考模型下的对数概率），并避免了PPO训练的不稳定性。

- **宪政AI（Constitutional AI）**（Bai等人，2022）自动化了对齐过程的部分环节。它不是收集人类比较数据，而是使用语言模型本身根据一组原则（"宪法"）批判和修改自己的输出，比如"选择危害较小的回复"。AI生成的比较然后用于偏好训练（RLAIF：基于AI反馈的RL）。

- **长上下文方法（Long-context methods）**解决标准自注意力的$O(n^2)$内存和计算成本问题，这限制了序列长度。当$n$增长到数万或数十万token时，标准注意力变得不可行。

- **稀疏注意力（Sparse attention）**用稀疏模式替换稠密的$n \times n$注意力矩阵，其中每个token只关注其他token的一个子集。常见模式包括**局部注意力（local attention）**（每个token关注固定大小的邻居窗口）、**步长注意力（strided attention）**（关注每第$k$个token）和**随机注意力（random attention）**（关注随机子集）。这些模式的组合（在BigBird、Longformer中使用）实现了$O(n)$或$O(n \sqrt{n})$复杂度，同时保持了捕获局部和全局依赖的能力。

![稀疏注意力模式](../../images/sparse_attention_patterns.svg)

- **滑动窗口注意力（Sliding window attention）**限制每个token仅关注前面的$w$个token（其局部窗口）。这导致$O(nw)$而不是$O(n^2)$，但长程信息必须通过跨层的重叠窗口传播。在$L$层和窗口大小$w$的情况下，有效感受野为$L \times w$个token。

- **环注意力（Ring attention）**通过将设备排列成环形拓扑，将长序列分布在多个设备上。每个设备持有序列的一个块，在为其块计算注意力的同时，将键值块发送给环中的下一个设备。计算与通信重叠，允许任意长度的序列，仅受所有设备总内存的限制，而不是任何一个单独设备的内存。

- **记忆增强模型（Memory-augmented models）**通过为Transformer配备外部记忆库来扩展上下文。在每一层，模型可以使用注意力从这个记忆中读取和写入。Memorizing Transformers缓存来自先前块的键值对，并在后续块中关注它们，有效地将上下文扩展到训练窗口之外。检索是近似的（使用缓存键上的$k$-最近邻）以保持效率。

- 以上方法是长上下文的**架构**解决方案。同样重要的是模型如何被**训练**以有效使用长上下文。

- **渐进式上下文扩展（Progressive context extension）**是标准方法。从一开始就在非常长的序列上训练成本极高（$O(n^2)$注意力成本），因此模型在短上下文长度（通常4K-8K token）上预训练，然后通过**继续预训练（continued pre-training）**分阶段扩展到目标长度。

- Llama 3.1从8K扩展到128K，通过800B token逐步增加序列长度。DeepSeek-V3在4K上训练，然后扩展到32K，再到128K。

- 每个阶段使用相对较少的token（相对于完整预训练预算），因为模型只需要学习如何使用更长的位置，而不需要重新学习语言本身。

- 位置编码必须在扩展期间进行调整。**RoPE插值（RoPE interpolation）**缩小位置索引，使模型看到与训练时相同的旋转角度，只是分布在更长的序列上。如果模型在长度$L$上训练，你想扩展到$L' = 4L$，则将所有位置索引除以4。

- 这意味着模型永远不会看到未遇到过的旋转角度，但相邻位置之间的有效分辨率会下降。

- **RoPE外推（RoPE extrapolation）**保持原始位置索引不变，简单地对超出$L$的位置应用RoPE，依赖模型泛化到未见过的角度。

- 插值要稳定得多；在没有基础频率调整（ABF）的情况下，外推会迅速退化。

- **YaRN**（Yet another RoPE extensioN）通过认识到并非所有RoPE维度应当被同等对待，改进了朴素插值。

- 高频维度（$\theta_i = \theta_{\text{base}}^{-2i/d}$中的小$i$）在训练长度内旋转多次，可以很好地外推。

- 低频维度（大$i$）旋转缓慢，对长度扩展更敏感。

- YaRN仅插值低频维度，外推高频维度，并对注意力logits应用温度缩放$t$以补偿分布偏移：

$$\text{score}'_{ij} = \frac{q_i^T k_j}{t \sqrt{d_k}}$$

- 其中$t > 1$使注意力分布平坦化，防止模型在位置信号被压缩时过度尖锐地关注附近token。

- **长上下文数据策展**是一个关键但常被低估的挑战。大多数预训练语料由短文档组成（新闻文章、网页、社交媒体帖子）。

- 长上下文训练需要一个真正锻炼完整上下文窗口的数据混合：书籍、代码仓库、长篇科学文章、多轮对话日志，以及主题相关的串联文档。

- 如果模型仅在短文档上训练，通过填充或打包填充上下文窗口，它学会了忽略远处的token，因为它们从不相关。

- **序列打包（Sequence packing）**是一种训练效率技术：将多个文档连接成单条训练序列以避免填充浪费，通过注意力掩码防止跨文档注意力。

- 对于长上下文训练，打包策略很重要：打包许多不相关的短文档教会模型远处的token是噪声，而打包更少的、真正长的文档教会它使用完整的上下文。

- 一个已知的失败模式是**"迷失在中间"（lost in the middle）**现象（Liu等人，2023）：语言模型倾向于有效使用上下文窗口开头和结尾的信息，但难以处理放在中间的信息。

- 这类似于人类记忆中的序列位置效应（首因和近因效应）。

- 它部分源于训练数据分布（重要信息通常在文档的开头或结尾）和注意力模式（注意力集中在附近和初始token上）。

- 长上下文训练中多样化地放置关键信息可以缓解但不能完全解决这一问题。

- **大海捞针（Needle-in-a-haystack）**评估测试模型是否能够在长干扰上下文（"干草堆"）的不同位置检索到特定事实（"针"）。

- 具有真正长上下文能力的模型应该无论针放在哪里都能实现近乎完美的检索。

- 这一测试清晰地揭示了"迷失在中间"效应，并被用于基准测试上下文扩展方法。

- **长上下文微调**在预训练之后使用有针对性的SFT数据：长多轮对话、证据分散在数千token中的文档QA、长篇摘要，以及代码仓库级别的代码理解。

- Qwen3在此阶段使用**双块注意力（Dual Chunk Attention，DCA）**，将长序列作为块对处理，块内注意力为全注意力，块间注意力为高效注意力，在微调期间实现了4倍的有效序列容量。

- **状态空间模型（State Space Models，SSM）**为长序列建模提供了一种根本不同的方法。它们不是修改注意力，而是用受连续时间控制理论启发的线性动力系统完全取代注意力。

- SSM将输入序列$u(t)$通过潜在状态$x(t) \in \mathbb{R}^N$映射到输出$y(t)$，满足：

$$x'(t) = Ax(t) + Bu(t), \quad y(t) = Cx(t) + Du(t)$$

- 其中$A \in \mathbb{R}^{N \times N}$是状态转移矩阵，$B \in \mathbb{R}^{N \times 1}$是输入投影，$C \in \mathbb{R}^{1 \times N}$是输出投影，$D$是跳跃连接。

- 要将其应用于离散序列（token），连续系统使用步长$\Delta$进行**离散化**。零阶保持离散化给出：

$$\bar{A} = \exp(\Delta A), \quad \bar{B} = (\Delta A)^{-1}(\exp(\Delta A) - I) \cdot \Delta B$$

- 离散递归然后变为$x_k = \bar{A} x_{k-1} + \bar{B} u_k$，$y_k = C x_k + D u_k$，这看起来像RNN：逐个处理token，带有隐状态。

- 与RNN不同，这个递归也可以展开为**全局卷积（global convolution）**：因为系统是线性的，输出为$y = \bar{K} \ast u$，其中核$\bar{K} = (C\bar{B}, \, C\bar{A}\bar{B}, \, C\bar{A}^2\bar{B}, \ldots)$仅依赖于固定参数。

- 这种**双重视图**——递归用于高效自回归推理（每步$O(1)$），卷积用于高效并行训练（通过FFT实现$O(n \log n)$）——是SSM的核心洞察。

![SSM双重视图：递归用于推理，卷积用于训练，以及Mamba的选择性扩展](../../images/ssm_dual_view.svg)

- **S4**（用于序列建模的结构化状态空间，Structured State Spaces for Sequence Modeling，Gu等人，2022）通过解决关键的数值挑战使SSM变得实用：状态矩阵$A$必须捕获长程依赖，但朴素地参数化它会导致梯度消失或爆炸（与普通RNN相同的问题）。

- S4使用**HiPPO**（高阶多项式投影算子，High-order Polynomial Projection Operators）矩阵初始化$A$，该矩阵源自连续信号最优多项式逼近理论。HiPPO矩阵具有特定结构，能够确保状态以优雅衰减的方式维持对整个输入历史的压缩表示：

```math
A_{nk} = -\begin{cases} (2n+1)^{1/2}(2k+1)^{1/2} & \text{if } n > k \\ n+1 & \text{if } n = k \\ 0 & \text{if } n < k \end{cases}
```

- 这种下三角结构确保状态使用勒让德多项式（Legendre polynomials）作为输入信号的在线近似。计算长核的$\bar{A}^k$代价很高，因此S4利用HiPPO矩阵可以分解为低秩项和对角项之和的性质，实现$O(n \log n)$的核计算。

- **Mamba**（Gu和Dao，2023）引入了关键创新——**选择性状态空间（selective state spaces）**：使SSM参数依赖于输入。在S4中，矩阵$A$、$B$、$C$和步长$\Delta$是固定的——无论内容如何，每token应用相同的动力学。Mamba使$B$、$C$和$\Delta$成为输入的函数：

$$B_k = \text{Linear}(u_k), \quad C_k = \text{Linear}(u_k), \quad \Delta_k = \text{softplus}(\text{Linear}(u_k))$$

- 这种选择性允许模型在每个位置决定将哪些信息存储在状态中、忽略哪些——类似于注意力如何选择相关token，但没有二次成本。步长$\Delta_k$控制"门"：大的$\Delta$使状态强力整合当前输入（连续动力学前进一个大步，有效地重置状态），而小的$\Delta$保留现有状态并忽略当前输入。

- 其代价是依赖输入的参数打破了卷积视图（核不再固定），因此Mamba不能使用基于FFT的训练。相反，它使用**硬件感知的并行扫描（hardware-aware parallel scan）**算法，利用递归的结合性：状态更新$(x_k, u_k) \mapsto x_{k+1}$可以表达为一系列结合操作，并使用前缀和（扫描）并行化，类似于硬件设计中的并行前缀加法。这在GPU上以$O(n)$时间运行，深度为$O(\log n)$，几乎匹配卷积的效率。

- Mamba实现了每token真正$O(1)$的推理（只需更新固定大小的状态，没有随上下文增长的KV缓存），使其在长序列长度下比Transformer从根本上更高效内存。状态大小$N$（通常为16）比存储$O(n \cdot d)$个值的Transformer KV缓存小得多。在实践中，Mamba在相同参数量的情况下，在语言建模基准上匹配或超过Transformer质量，并且在长序列上有显著更快的推理速度。

- **混合架构（Hybrid architectures）**将SSM层与注意力层结合，在大多数层使用SSM（高效的长程传播），并穿插少量注意力层（精确的基于内容的检索）。Jamba和Zamba等模型交错Mamba和Transformer块，在保持大部分推理效率优势的同时实现比纯SSM更好的质量。这表明注意力和SSM捕获互补的能力：SSM擅长平滑、长程的状态传播，而注意力擅长精确的、依赖内容的查找。

- **检索增强生成（Retrieval-Augmented Generation，RAG）**通过在推理时赋予语言模型访问外部知识库的能力，解决了语言模型的知识局限。RAG不依赖于仅在训练期间编码在模型参数中的知识，而是检索相关文档，并根据这些文档条件生成。

- 经典的**检索器-阅读器架构（retriever-reader architecture）**有两个组件。**检索器（retriever）**接受一个查询，从语料库中获取top-$k$个最相关的段落。**阅读器（reader）**（一个语言模型）根据查询和检索到的段落生成答案。检索器可以使用稀疏方法（BM25，扩展自第02章的TF-IDF）或稠密方法。

- **稠密段落检索（Dense Passage Retrieval，DPR）**使用双编码器架构：一个编码器将问题映射为向量，另一个将段落映射为向量。两者通常基于BERT。在索引时，所有段落被编码并存储。在查询时，问题被编码，使用近似最近邻搜索（如FAISS）找到最近的段落。相似度度量是问题和段落向量之间的点积。

- **分块策略（Chunking strategies）**显著影响检索质量。文档必须被分割成检索器能处理但又能包含完整思想的足够小的段落。固定大小分块（例如256个token，50个token重叠）简单但可能会尴尬地拆分句子。语义分块在段落或章节边界处拆分。层级分块创建不同粒度的摘要树。

![RAG架构](../../images/rag_architecture.svg)

- RAG提供了几个优势：知识库可以在不重新训练模型的情况下更新，模型可以引用来源，并且由于模型可以将其答案建立在检索到的文本基础上，幻觉（hallucination）得以减少。主要挑战是检索质量（如果检索到错误的段落，模型可能自信地产生错误答案）和延迟（检索为推理增加了一个步骤）。

- **推测解码（Speculative decoding）**通过使用一个小型、快速的**草稿模型（draft model）**并行提议多个token，然后由大型**目标模型（target model）**在单次前向传播中验证，来加速自回归生成。

- 算法工作如下：草稿模型自回归地生成$k$个候选token（这很快，因为草稿模型很小）。

- 然后目标模型在单次前向传播中同时对所有$k$个token评分（这很高效，因为工作被批处理）。

- 对于从草稿分布$p_d(t)$中采样的每个候选token $t$，它以概率$\min(1, \, p_{\text{target}}(t) / p_d(t))$被接受。如果被拒绝，从**调整分布（adjusted distribution）**$p_{\text{adj}}(t) = \max(0, \, p_{\text{target}}(t) - p_d(t))$（归一化后）重新采样一个校正token。

- 这种接受-拒绝方案保证输出分布与仅使用目标模型相同。

- 要理解为什么，考虑发射token $t$的有效概率。它可以直接被接受（概率$p_d(t) \cdot \min(1, p_{\text{target}}(t)/p_d(t))$）或通过重新采样产生。

- 对于$p_{\text{target}}(t) \leq p_d(t)$的token，直接接受贡献$p_{\text{target}}(t)$。对于$p_{\text{target}}(t) > p_d(t)$的token，直接接受贡献$p_d(t)$，重新采样贡献余数$p_{\text{target}}(t) - p_d(t)$（在考虑拒绝概率之后）。

- 在两种情况下，发射$t$的总概率等于$p_{\text{target}}(t)$。草稿模型只影响速度，不影响质量。

![推测解码](../../images/speculative_decoding.svg)

- 加速比取决于接受率：如果草稿模型与目标模型对齐良好，大多数token被接受，墙上时钟时间大致相当于草稿模型。典型的加速比为2-3倍，且没有质量下降。

- **Medusa**（Cai等人，2024）采取不同方法：它不在目标模型之外使用单独的草稿模型，而是为目标模型本身添加多个轻量级预测头。每个头同时预测一个不同的未来token位置（分别提前$k = 1, 2, 3, \ldots$步）。在每一步，Medusa使用树结构提议几个候选续写，目标模型注意力层的单次前向传播验证哪些候选是一致的。这完全避免了单独草稿模型的需要。

- **并行生成（Parallel generation）**方法更广泛地旨在打破自回归解码的串行瓶颈。Jacobi解码用猜测值初始化所有位置，并迭代并行细化直到收敛，将生成视为定点迭代。非自回归模型（Non-autoregressive models，NAT）在单次前向传播中同时生成所有token，但通常会有质量下降，需要迭代细化、CTC损失或从自回归教师进行知识蒸馏等技术来缩小差距。

- 以上技术——对齐、长上下文、检索、高效解码、状态空间模型——汇聚在现代生产级LLM中。

- 本章剩余部分概览前沿模型的架构创新，展示第01-04章的理论思想和上述方法如何结合在实践中。

- **分组查询注意力（Grouped Query Attention，GQA）**是最广泛采用的注意力效率技术。标准多头注意力（MHA）为每个头维护单独的键和值投影，每个token需要缓存$n_{\text{heads}} \times d_{\text{head}}$个值。GQA将多个查询头分组共享单个键值头。

- 拥有64个查询头和8个KV头（Llama 3、Qwen、Gemma中的常见配置），每个KV头由8个查询头共享，与MHA相比将KV缓存减少了8倍。

- 输出质量几乎与MHA相同，因为查询仍然可以关注不同的模式，它们只是共享相同的键值子空间。多查询注意力（Multi-Query Attention，MQA）是极端情况，所有查询共享单个KV头，但GQA提供了更好的质量-效率权衡。

- **多头潜在注意力（Multi-head Latent Attention，MLA）**，在DeepSeek-V2中引入，实现了更激进的KV缓存压缩。MLA不缓存完整的键值投影（即使是GQA），而是将隐状态下投影到一个低秩**潜在向量（latent vector）**$c_t \in \mathbb{R}^{d_c}$，其中$d_c \ll n_{\text{heads}} \times d_{\text{head}}$：

$$c_t = W_{\text{down}} \, h_t$$

- 只有这个压缩向量被缓存。在注意力计算时，完整的键和值表示通过上投影重建：$k_t = W_{\text{up}}^K c_t$，$v_t = W_{\text{up}}^V c_t$。在DeepSeek-V3（671B总参数，37B活跃参数）中，压缩维度为$d_c = 512$，对比完整MHA的$128 \times 128 = 16{,}384$，KV缓存减少了93%。

- 一个微妙之处：标准RoPE依赖位置，与共享压缩不兼容，因此MLA使用**解耦RoPE（decoupled RoPE）**：查询和键的一个小的独立流（每个头64维）通过RoPE携带位置信息，而大部分表示流经压缩的潜在路径。

![注意力KV缓存策略：MHA、GQA和MLA的比较](../../images/mla_vs_gqa.svg)

- **规模级的位置编码**已与原始正弦方案显著分道扬镳。所有前沿模型都使用**RoPE**（第04章），但针对长上下文进行了关键修改。原始RoPE公式$\theta_i = \theta_{\text{base}}^{-2i/d}$中的基础频率$\theta_{\text{base}}$通常为10,000，这限制了在训练长度之外的外推能力。

- **调整基础频率（Adjusted Base Frequency，ABF）**简单地将$\theta_{\text{base}}$增加到500,000（Llama 3）或1,000,000（Qwen3、Gemma 3），拉伸旋转周期，使模型在训练期间遇到更少的完整旋转，从而能够进一步外推。

- **YaRN**（Yet another RoPE extensioN）应用频率依赖的插值：低频维度被插值（缩放），高频维度被外推，并通过温度因子调整注意力分布。DeepSeek-V3、Qwen和Kimi K2都使用基于YaRN的扩展，从4K-8K预训练的模型达到128K上下文。

- **iRoPE**（交错RoPE，interleaved RoPE），在Llama 4中引入，采取更激进的方法：每第4个注意力层使用**无位置编码（NoPE）**，而其他层使用带分块注意力的标准RoPE。

- NoPE层可以关注所有位置而不带任何位置偏差，而RoPE层提供局部排序。结合推理时的温度缩放，这使Llama 4 Scout的10M token上下文窗口成为可能——比任何纯RoPE方法高出数个数量级。

- **规模级的混合专家**已成为前沿模型的主导架构（第04章介绍了MoE基础）。关键设计选择是专家数量、路由稀疏度和负载均衡。

- **路由稀疏度**差异显著：DeepSeek-V3使用256个专家和top-8路由（32倍稀疏度），Qwen3使用128个专家和top-8（16倍稀疏度），Mixtral使用8个专家和top-2（4倍稀疏度），Llama 4 Maverick使用128个专家和top-1加一个共享专家（128倍稀疏度）。

- 更高的稀疏度意味着在相同活跃计算下有更多的总参数量，但需要更仔细的负载均衡和通信基础设施。

- **无辅助损失的负载均衡（Auxiliary-loss-free load balancing）**（DeepSeek-V3）取代了传统上被发现会降低模型质量的负载均衡损失（第04章）。相反，每个专家维护一个每训练步调整的动态偏置项：过载专家降低其偏置（接收更少token），欠载专家提高其偏置。这实现了均衡的路由，没有任何辅助损失污染主训练信号。

- **共享专家（Shared experts）**出现在大多数MoE设计中：一个或多个专家FFN处理每个token，无论路由决策如何。这些处理所有token都需要的常见模式（基本句法、功能词），解放路由专家去专门化。Llama 4使用1个共享专家加1个路由专家（非常稀疏）；DeepSeek-V3使用1个共享加8个路由。

- **交替稠密和MoE层**提供了另一个设计轴。Gemma 2和3交替局部/全局注意力层（Gemma 3中为5:1比例，其中局部层使用1,024 token的滑动窗口，只有全局层缓存完整的128K上下文）。

- Llama 4 Maverick将稠密FFN层与MoE层交错。Kimi K2使用混合稀疏层（在专家层之间穿插一个稠密层）。这种异构设计允许不同的层服务于不同的功能。

- **多token预测（Multi-token prediction，MTP）**，在DeepSeek-V3中使用，训练模型不仅预测下一个token，还预测再下一个token。在每个位置，一个次要预测模块（共享主模型的嵌入）预测一个额外的未来token。MTP损失相对于主下一个token损失的权重为0.1-0.3。除了在训练期间提高表示质量外，MTP头可以在推理时作为推测解码的草稿头，提供免费的加速。

- **知识蒸馏（Knowledge distillation）**是一种训练策略，其中大型"教师"模型的输出指导较小"学生"模型的训练。Gemma 2和3广泛使用蒸馏：较小的模型（2B、4B）在50倍计算最优的数据量上训练，使用教师的概率分布作为软目标。这就是为什么Gemma 3-4B在质量上匹配Gemma 2-27B。

- 蒸馏损失取代或补充标准交叉熵：学生最小化其输出分布与教师之间的KL散度：

$$\mathcal{L}_{\text{distill}} = D_{\text{KL}}(p_{\text{teacher}}(\cdot \mid x) \| p_{\text{student}}(\cdot \mid x))$$

- DeepSeek-R1使用800K精心策划的思维链样本，将其671B推理模型蒸馏为小至1.5B的稠密模型，产生了具有不成比例强大推理能力的小模型。

- **通过强化学习的推理（Reasoning via reinforcement learning）**代表了LLM能力方面最近最重要的进展。DeepSeek-R1证明了对基础模型进行纯强化学习（无需监督微调）可以引发出思维链推理、自我验证和错误纠正——当模型因正确的最终答案而获得奖励时，这些行为会自发涌现。

- DeepSeek-R1使用**GRPO**（分组相对策略优化，Group Relative Policy Optimisation），消除了PPO所需的价值网络。对于每个提示，GRPO采样一组$G$个输出，计算它们的奖励，并在组内归一化优势：

$$A_i = \frac{r_i - \text{mean}(r_1, \ldots, r_G)}{\text{std}(r_1, \ldots, r_G)}$$

- 策略梯度然后使用这些分组相对优势与裁剪目标（类似于PPO的裁剪）。

- 消除批评家网络将RL训练的内存和计算需求减半，使得用RL训练671B参数模型变得可行。

- 一个关键设计选择：DeepSeek-R1使用**基于规则的奖励（rule-based rewards）**（根据标准答案检查数学答案，运行代码测试用例）而不是神经奖励模型，因为神经奖励模型在此规模下被发现有奖励欺骗的倾向。

- **Qwen3的混合思维模式**将推理（使用`<think>`标签进行逐步思维链）和快速直接回复集成到单个模型中，允许用户控制"思考预算"，在延迟和推理深度之间做权衡。

- 这是通过同时在思维和非思维数据上训练来实现的，而不是通过分离的模型检查点。

- **规模级的训练稳定化**需要超越标准实践的新技术。**Logit软截断（Logit soft-capping）**（Gemma 2）通过$s \cdot \tanh(\text{logits} / s)$传递注意力分数，使用软上限$s$（通常30-50）以防止无界增长。

- **QK-Norm**（Qwen3）在计算注意力分数之前对查询和键向量应用RMSNorm，取代了对QKV偏置的需求。**QK-Clip**（Kimi K2的MuonClip优化器）在训练期间监控最大注意力logit，并在超过阈值时重新缩放查询-键权重矩阵，使1T参数模型能够稳定预训练且零不稳定事件。

- **FP8混合精度训练（FP8 mixed-precision training）**（DeepSeek-V3）在前向和反向传播的计算密集型矩阵乘法中使用8位浮点数，同时将主权重保持在高精度。

- 与BF16/FP16训练相比，这大约使吞吐量翻倍，且质量损失可忽略。DeepSeek-V3仅用2.8M H800 GPU小时训练了其671B参数的模型——仅为可比模型的一小部分——主要是由于这一优化和其他工程优化。

## 编程任务（在CoLab或notebook中使用）

1. 从零实现一个简单的检索增强生成流水线。使用TF-IDF（第02章）索引一组文档，检索与查询最相关的段落，并将其前置到提示中。
```python
import jax.numpy as jnp
import math
from collections import Counter

# Knowledge base: a set of short passages
knowledge_base = [
    "The Eiffel Tower is a wrought-iron lattice tower in Paris, France. It was constructed from 1887 to 1889 as the centerpiece of the 1889 World's Fair.",
    "The Great Wall of China is a series of fortifications built along the northern borders of China. Construction began in the 7th century BC.",
    "Photosynthesis is the process by which plants convert sunlight, water, and carbon dioxide into glucose and oxygen using chlorophyll.",
    "The theory of general relativity, published by Albert Einstein in 1915, describes gravity as the curvature of spacetime caused by mass and energy.",
    "Python is a high-level programming language known for its simple syntax and readability. It was created by Guido van Rossum and released in 1991.",
    "The mitochondria are organelles found in eukaryotic cells. They generate most of the cell's supply of ATP, used as a source of chemical energy.",
]

# Build TF-IDF index (reusing concepts from file 02)
def tokenise(text):
    return text.lower().split()

vocab = sorted(set(w for doc in knowledge_base for w in tokenise(doc)))
word2idx = {w: i for i, w in enumerate(vocab)}
V = len(vocab)
N = len(knowledge_base)

# Document frequencies
doc_freq = Counter()
for doc in knowledge_base:
    for w in set(tokenise(doc)):
        doc_freq[w] += 1

def tfidf_vector(text):
    words = tokenise(text)
    counts = Counter(words)
    vec = jnp.zeros(V)
    for w, c in counts.items():
        if w in word2idx:
            tf = 1 + math.log(c)
            idf = math.log(N / (doc_freq.get(w, 0) + 1))
            vec = vec.at[word2idx[w]].set(tf * idf)
    return vec

# Index all documents
doc_vectors = jnp.stack([tfidf_vector(doc) for doc in knowledge_base])

def cosine_sim(a, b):
    return jnp.dot(a, b) / (jnp.linalg.norm(a) * jnp.linalg.norm(b) + 1e-8)

def retrieve(query, top_k=2):
    """Retrieve top-k most relevant passages for a query."""
    q_vec = tfidf_vector(query)
    sims = jnp.array([cosine_sim(q_vec, doc_vectors[i]) for i in range(N)])
    top_indices = jnp.argsort(-sims)[:top_k]
    return [(int(i), float(sims[i]), knowledge_base[int(i)]) for i in top_indices]

# Test retrieval
queries = [
    "Who built the Eiffel Tower?",
    "How do plants make food?",
    "What did Einstein discover?",
]

for query in queries:
    results = retrieve(query, top_k=1)
    print(f"\nQuery: '{query}'")
    for idx, sim, passage in results:
        print(f"  Retrieved (sim={sim:.3f}): '{passage[:80]}...'")

    # RAG-style prompt construction
    context = results[0][2]
    rag_prompt = f"Context: {context}\n\nQuestion: {query}\nAnswer:"
    print(f"  RAG prompt:\n    {rag_prompt[:120]}...")
```

2. 使用玩具草稿模型和目标模型实现推测解码。展示接受的输出与目标模型的分布匹配。
```python
import jax
import jax.numpy as jnp

# Simulate a draft model (fast, less accurate) and target model (slow, accurate)
vocab_size = 8
seq_len = 5

key = jax.random.PRNGKey(42)

# Target model: returns logits given a sequence
def target_model(seq, key):
    """Simulated target model: produces token logits (expensive)."""
    # In practice this would be a large Transformer forward pass
    k1, k2 = jax.random.split(key)
    logits = jax.random.normal(k1, (len(seq), vocab_size)) * 2
    # Make it somewhat predictable: bias toward token (seq[-1] + 1) % vocab_size
    for i in range(len(seq)):
        logits = logits.at[i, (seq[i] + 1) % vocab_size].add(3.0)
    return logits

def draft_model(seq, key):
    """Simulated draft model: similar but noisier (cheap)."""
    k1, k2 = jax.random.split(key)
    logits = jax.random.normal(k1, (len(seq), vocab_size))
    for i in range(len(seq)):
        logits = logits.at[i, (seq[i] + 1) % vocab_size].add(2.0)
    return logits

def sample_token(logits, key):
    return jax.random.categorical(key, logits)

def speculative_decode(prefix, draft_steps=3, key=jax.random.PRNGKey(0)):
    """Speculative decoding: draft proposes, target verifies."""
    seq = list(prefix)
    total_accepted = 0
    total_proposed = 0

    for _ in range(4):  # generate 4 rounds
        key, *subkeys = jax.random.split(key, draft_steps + 3)

        # Draft model proposes draft_steps tokens
        draft_tokens = []
        draft_probs = []
        draft_seq = list(seq)
        for i in range(draft_steps):
            d_logits = draft_model(jnp.array(draft_seq), subkeys[i])
            d_probs = jax.nn.softmax(d_logits[-1])
            tok = sample_token(d_logits[-1], subkeys[i])
            draft_tokens.append(int(tok))
            draft_probs.append(d_probs)
            draft_seq.append(int(tok))

        # Target model scores all draft tokens in one pass
        target_logits = target_model(jnp.array(draft_seq), subkeys[draft_steps])
        target_start = len(seq) - 1  # position of last prefix token

        # Accept/reject each draft token
        accepted = 0
        for i in range(draft_steps):
            t_probs = jax.nn.softmax(target_logits[target_start + i])
            d_prob = draft_probs[i][draft_tokens[i]]
            t_prob = t_probs[draft_tokens[i]]

            # Accept with probability min(1, target_prob / draft_prob)
            accept_prob = jnp.minimum(1.0, t_prob / (d_prob + 1e-10))
            key, accept_key = jax.random.split(key)
            if jax.random.uniform(accept_key) < accept_prob:
                seq.append(draft_tokens[i])
                accepted += 1
            else:
                # Reject: sample from adjusted distribution
                key, resample_key = jax.random.split(key)
                adjusted = jnp.maximum(0, t_probs - draft_probs[i])
                adjusted = adjusted / (adjusted.sum() + 1e-10)
                new_tok = jax.random.categorical(resample_key, jnp.log(adjusted + 1e-10))
                seq.append(int(new_tok))
                break

        total_accepted += accepted
        total_proposed += draft_steps

    return seq, total_accepted, total_proposed

# Run speculative decoding
prefix = [0, 1]
result_seq, accepted, proposed = speculative_decode(prefix)
acceptance_rate = accepted / proposed if proposed > 0 else 0

print(f"Prefix: {prefix}")
print(f"Generated sequence: {result_seq}")
print(f"Draft proposals: {proposed}")
print(f"Accepted: {accepted}")
print(f"Acceptance rate: {acceptance_rate:.1%}")
print(f"Speedup potential: {(accepted + proposed) / proposed:.2f}x")
```

3. 构建一个简单的DPO训练循环。给定偏好的和不被偏好的回复对，使用DPO损失更新一个小模型。
```python
import jax
import jax.numpy as jnp

# Tiny language model: linear projection from one-hot to logits
vocab_size = 10
seq_len = 4

key = jax.random.PRNGKey(42)
k1, k2 = jax.random.split(key)

# Current policy parameters (trainable)
theta = jax.random.normal(k1, (vocab_size, vocab_size)) * 0.1
# Reference policy parameters (frozen copy of initial theta)
theta_ref = theta.copy()

def log_prob_sequence(params, sequence):
    """Compute log P(sequence) under a simple autoregressive model."""
    total = 0.0
    for t in range(1, len(sequence)):
        # Simple: logits at position t depend on token at t-1
        logits = params[sequence[t-1]]
        log_probs = jax.nn.log_softmax(logits)
        total += log_probs[sequence[t]]
    return total

def dpo_loss(theta, theta_ref, preferred, dispreferred, beta=0.1):
    """Direct Preference Optimisation loss for one pair."""
    log_pi_w = log_prob_sequence(theta, preferred)
    log_pi_l = log_prob_sequence(theta, dispreferred)
    log_ref_w = log_prob_sequence(theta_ref, preferred)
    log_ref_l = log_prob_sequence(theta_ref, dispreferred)

    # DPO objective
    return -jax.nn.log_sigmoid(
        beta * ((log_pi_w - log_ref_w) - (log_pi_l - log_ref_l))
    )

# Preference dataset: (prompt_prefix, preferred_completion, dispreferred_completion)
preferences = [
    (jnp.array([1, 3, 5, 7]), jnp.array([1, 3, 5, 2])),  # prefer 7 over 2 at end
    (jnp.array([0, 2, 4, 6]), jnp.array([0, 2, 4, 9])),  # prefer 6 over 9
    (jnp.array([3, 3, 3, 3]), jnp.array([3, 3, 3, 0])),  # prefer repeating over 0
    (jnp.array([5, 6, 7, 8]), jnp.array([5, 6, 7, 1])),  # prefer 8 over 1
]

grad_fn = jax.jit(jax.grad(dpo_loss))
lr = 0.05

print("Training DPO...")
for epoch in range(100):
    total_loss = 0.0
    for preferred, dispreferred in preferences:
        loss = dpo_loss(theta, theta_ref, preferred, dispreferred)
        grads = grad_fn(theta, theta_ref, preferred, dispreferred)
        theta = theta - lr * grads
        total_loss += loss
    if (epoch + 1) % 20 == 0:
        avg_loss = total_loss / len(preferences)
        print(f"  Epoch {epoch+1}: avg DPO loss = {avg_loss:.4f}")

# Check: the model should now prefer the preferred completions
print("\nPreference check after DPO training:")
for preferred, dispreferred in preferences:
    lp_w = log_prob_sequence(theta, preferred)
    lp_l = log_prob_sequence(theta, dispreferred)
    print(f"  Preferred {list(preferred.astype(int))}: logP={lp_w:.3f}  "
          f"Dispreferred {list(dispreferred.astype(int))}: logP={lp_l:.3f}  "
          f"{'correct' if lp_w > lp_l else 'WRONG'}")
```
