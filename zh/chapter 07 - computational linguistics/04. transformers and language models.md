# Transformer与语言模型（Transformers and Language Models）

*Transformer用自注意力机制取代了循环结构，成为语言理解和生成的主导架构。本章涵盖BERT、GPT、T5、位置编码（正弦式、RoPE）、预训练目标（MLM、CLM）、微调、提示工程和缩放定律——现代大型语言模型（LLM）背后的蓝图。*

- 在第06章中，我们介绍了Transformer架构：自注意力、多头注意力、位置编码和编码器-解码器结构。本章着重讨论Transformer如何适应特定的NLP范式、定义了现代NLP的模型（BERT、GPT、T5），以及使它们在大规模下实用的技术。

- 回顾核心操作：**缩放点积注意力（Scaled dot-product attention）**计算$\text{softmax}(QK^T / \sqrt{d_k}) V$，其中查询、键和值是输入的线性投影。**多头注意力（Multi-head attention）**运行$h$个并行的注意力头，每个头有不同的学习投影，并将结果拼接起来。Transformer块将此与残差连接、层归一化和逐位置前馈网络（第06章）包裹在一起。

- 一个微妙但重要的架构选择是**层归一化（Layer Normalisation）**的位置。原始Transformer使用**后归一化（post-norm）**：残差和归一化在子层之后，如$\text{LayerNorm}(x + \text{Sublayer}(x))$。

- 大多数现代模型使用**前归一化（pre-norm）**：在子层之前归一化，如$x + \text{Sublayer}(\text{LayerNorm}(x))$。前归一化在训练期间更稳定，因为残差连接通过恒等路径直接传递梯度，而不受归一化的影响。这使得训练非常深的模型变得更容易，无需仔细调整学习率预热。

- 每个Transformer块中的**前馈子层（Feed-forward sublayer）**是一个独立应用于每个token位置的两层MLP：

$$\text{FFN}(x) = W_2 \cdot \text{GELU}(W_1 x + b_1) + b_2$$

- 内部维度通常是模型维度的4倍（例如，$d_{\text{model}} = 768$，$d_{\text{ff}} = 3072$）。该FFN约占每个块中三分之二的参数量，被认为起到键值记忆的作用，存储在训练期间学到的知识。

- **位置编码（Positional encoding）**为模型提供关于token顺序的信息，因为注意力本身是排列等变的。原始的**正弦编码（sinusoidal encoding）**（第06章）使用不同频率的固定正弦和余弦函数。**可学习的位置嵌入（Learned positional embeddings）**简单地添加每个位置的可训练向量（BERT和GPT-2中使用）。两者都是绝对编码：位置5获得相同的向量，无论上下文如何。

- **旋转位置嵌入（Rotary Position Embedding，RoPE）**通过在2D子空间中旋转查询和键向量来编码位置。对于一对维度$(q_{2i}, q_{2i+1})$，旋转角度$m\theta_i$（其中$m$是位置，$\theta_i = 10000^{-2i/d}$）应用于：

```math
\begin{bmatrix} q'_{2i} \\ q'_{2i+1} \end{bmatrix} = \begin{bmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i \end{bmatrix} \begin{bmatrix} q_{2i} \\ q_{2i+1} \end{bmatrix}
```

![RoPE：每个位置在2D子空间中以不同角度旋转查询和键向量，因此注意力分数只依赖于相对位置](../../images/rope_rotation.svg)

- RoPE的美妙之处在于旋转后的查询和键之间的点积$q'^T k'$只依赖于相对位置$m - n$，而非绝对位置。

- 要理解原因，将旋转写为$q' = R_m q$和$k' = R_n k$，其中$R_m$是块对角旋转矩阵。注意力分数变为：

$$q'^T k' = (R_m q)^T (R_n k) = q^T R_m^T R_n \, k = q^T R_{n-m} \, k$$

- 最后一步由旋转群的性质得出：$R_m^T R_n = R_{n-m}$（旋转回$m$再向前旋转$n$等于旋转$n - m$）。

- 这意味着注意力分数只依赖于相对距离$n - m$，而不是绝对位置$m$和$n$各自的值。

- 模型在没有学习任何位置参数的情况下获得了自然的距离概念，并且能够泛化到训练期间未见过的序列长度。

- **ALiBi**（带线性偏置的注意力，Attention with Linear Biases）采取了更简单的方法：它根据距离在注意力分数上添加一个固定的线性惩罚，$\text{score}_{ij} = q_i^T k_j - m \cdot |i - j|$，其中$m$是每个头特定的斜率。不同的头使用不同的斜率，允许某些头局部关注，而其他头全局关注。ALiBi不需要学习位置参数，并能很好地泛化到比训练时更长的序列。

- 基于Transformer的语言模型的三种主导范式是**仅编码器（encoder-only）**、**仅解码器（decoder-only）**和**编码器-解码器（encoder-decoder）**。它们在模型能看到什么（注意力掩码）以及如何训练上有所不同。

![三种Transformer范式：仅编码器（BERT）具有双向注意力用于分类，仅解码器（GPT）具有因果注意力用于生成，编码器-解码器（T5）结合两者用于seq2seq任务](../../images/transformer_paradigms.svg)

- **BERT**（基于Transformer的双向编码器表示，Bidirectional Encoder Representations from Transformers，Devlin等人，2019）是典型的仅编码器模型。它以完全双向的注意力处理文本：每个token可以关注每个其他token，无论是左边还是右边。这为BERT提供了丰富的上下文表示，但意味着它不能自回归地生成文本。

- BERT使用两个目标进行预训练。**掩码语言建模（Masked Language Modelling，MLM）**随机掩码15%的输入token，并训练模型预测它们。在被选中的token中，80%替换为[MASK] token，10%替换为随机词，10%保持不变（以防止模型学习到只在看到[MASK]时才预测）。训练目标为：

$$\mathcal{L}_{\text{MLM}} = -\sum_{i \in \mathcal{M}} \log P(w_i \mid w_{\backslash \mathcal{M}})$$

- 其中$\mathcal{M}$是被掩码位置的集合，$w_{\backslash \mathcal{M}}$是那些位置被掩码后的句子。这是一个**去噪（denoising）**目标：模型学习重建被破坏的输入。

![BERT掩码语言建模：输入中15%的token被掩码，双向Transformer预测被掩码位置上的原始token](../../images/bert_mlm.svg)

- **下一句预测（Next Sentence Prediction，NSP）**训练BERT预测两个句子在原始文本中是否连续。输入开头的一个特殊[CLS] token用于此二分类任务。NSP被引入是为了帮助诸如问答之类的需要理解句子关系的任务，尽管后续工作（RoBERTa）表明它贡献很小，可以被舍弃。

- BERT的预训练表示通过在其上加一个任务特定的头（一个简单的线性层）并对整个模型进行微调来适应下游任务。对于分类任务，使用[CLS] token的表示。对于token级任务（NER、词性标注），使用每个token的表示。这种**微调（fine-tuning）**方法将预训练期间学到的语言知识迁移到新任务上，只需相对较少的标注数据。

- **GPT**（生成式预训练Transformer，Generative Pre-trained Transformer，Radford等人，2018）是典型的仅解码器模型。它使用**因果（自回归）注意力（causal/autoregressive attention）**：每个token只能关注更早位置（及其自身）的token。这是通过在注意力矩阵中掩码未来位置来实现的（在softmax之前将其分数设置为$-\infty$）。训练目标是简单的**因果语言建模（causal language modelling）**：给定所有先前的token，预测下一个token。

$$\mathcal{L}_{\text{CLM}} = -\sum_{i=1}^{n} \log P(w_i \mid w_1, \ldots, w_{i-1})$$

- 这与第02章中的n元语法语言模型目标是相同的，但使用了Transformer参数化，能够以全部前文为条件，而不仅仅是最后$k-1$个token。

- **GPT-2**将其扩展到15亿参数，并展示了强大的零样本（zero-shot）性能：无需任何微调，它可以通过以自然语言提示（"Translate English to French: ..."）为条件来执行任务。

- **GPT-3**（1750亿参数）表明，仅靠规模就能实现**上下文学习（in-context learning）**：通过在提示中提供少量输入-输出示例，模型可以在没有任何梯度更新的情况下执行新任务。

- **编码器-解码器模型**如**T5**（文本到文本迁移Transformer，Text-to-Text Transfer Transformer，Raffel等人，2020）将每个NLP任务框架化为文本到文本：输入是一个文本字符串（可能带有任务前缀，如"translate English to German:"），输出是一个文本字符串。编码器以双向注意力处理输入，解码器以对编码器的交叉注意力自回归地生成输出。

- T5使用**片段破坏（span corruption）**进行预训练：连续的随机token片段被替换为哨兵token，模型必须生成原始token。例如，"The cat sat on the mat"可能变为"The [X] on [Y]"作为输入，目标为"[X] cat sat [Y] the mat"。这是BERT的MLM向片段而非单个token的推广。

- **BART**（Lewis等人，2020）是另一个使用去噪目标预训练的编码器-解码器模型，但它应用了更广泛的破坏策略：token掩码、token删除、片段掩码、句子置换和文档旋转。破坏的多样性迫使模型学习更鲁棒的表示。

- 随着语言模型变得越来越大，**全量微调（full fine-tuning）**（更新所有参数）变得不切实际：一个175B参数的模型仅存储优化器状态就需要数百GB。**参数高效微调（Parameter-Efficient Fine-Tuning，PEFT）**方法只调整一小部分参数。

- **适配器（Adapters）**在现有的Transformer层之间插入小的瓶颈层（通常两个线性层加一个非线性：下投影到一个小的维度，然后再上投影回来）。只有适配器的权重被训练；原始模型权重被冻结。这增加了不到5%的新参数，同时在大多数任务上匹配全量微调的性能。

- **LoRA**（低秩适配，Low-Rank Adaptation）修改权重矩阵本身，而不添加新层。LoRA不更新完整的权重矩阵$W$，而是学习更新的低秩分解：$W' = W + BA$，其中$B$是$d \times r$，$A$是$r \times d$，且$r \ll d$（通常$r = 4$到$r = 64$）。原始的$W$被冻结；只有$A$和$B$被训练。在推理时，更新可以被合并到原始权重中，没有额外的延迟：

$$W' = W + BA$$

![LoRA：冻结的权重矩阵W被通过小型矩阵A和B的低秩路径绕过，将可训练参数减少32倍，同时匹配全量微调](../../images/lora_decomposition.svg)

- **前缀调优（Prefix tuning）**在每个注意力层的键和值矩阵前面附加一系列可学习的"虚拟token"。模型关注这些前缀向量，就像它们是真实的token一样，只有前缀参数被训练。这类似于提示调优（prompt tuning），但操作在激活空间而非嵌入空间。

- **提示工程（Prompt engineering）**是设计输入文本以激发预训练模型产生期望行为的艺术，不需要任何参数更新。

    - **零样本提示（Zero-shot prompting）**用自然语言描述任务（"对以下评论的情感进行分类："）。

    - **少样本提示（Few-shot prompting）**在实际查询之前提供输入-输出示例。

    - **思维链（Chain-of-thought，CoT）提示**添加"让我们一步一步思考"或在示例中包含推理轨迹，通过引导模型分解问题，显著提高算术和逻辑推理任务的性能。

- **上下文学习（In-context learning，ICL）**是一种现象，即大型语言模型能够从提示中提供的示例学习执行任务，而不需要任何梯度更新。模型的权重不改变；它使用示例作为一种隐式的规范。

- ICL的机制如何运作仍是一个活跃的研究问题；一种假说是注意力层在其前向传播中实现了某种形式的梯度下降，有效地对上下文中的示例进行"训练"。

- **缩放定律（Scaling laws）**描述了模型大小、数据大小、计算预算和性能（以损失衡量）之间的可预测关系。Kaplan等人（2020）发现损失在每个变量上服从幂律：

$$L(N) \propto N^{-\alpha_N}, \quad L(D) \propto D^{-\alpha_D}, \quad L(C) \propto C^{-\alpha_C}$$

- 其中$N$是参数数量，$D$是数据集大小，$C$是计算预算。这些幂律在多个数量级上成立，表明简单地扩大规模就能产生可预测的改进。

![缩放定律：在对数-对数坐标轴上，损失以幂律下降，Kaplan和Chinchilla的发现都表明随规模扩大有可预测的改进](../../images/scaling_laws.svg)

- **Chinchilla缩放定律**（Hoffmann等人，2022）修正了这一点，表明大多数大型模型训练不足。对于固定的计算预算$C$，最优分配应以相等的比例缩放模型大小和训练数据：

$$N_{\text{opt}} \propto C^{0.5}, \quad D_{\text{opt}} \propto C^{0.5}$$

- 这意味着如果你将计算预算翻倍，你应该将模型大小和数据集大小都增加$\sqrt{2}$倍，而不是只让模型变大。

- Kaplan等人曾建议$N$的缩放速度快于$D$，这导致了非常大但训练不足的模型。Chinchilla（70B参数，1.4T token）以相同的计算预算匹配了Gopher（280B参数，300B token）的性能，证明了早期模型严重缺乏数据。

- 经验法则：每个参数大约训练20个token。

- **混合专家（Mixture of Experts，MoE）**是一种在不按比例增加计算量的情况下扩展模型容量的架构。MoE不采用一个大的前馈层，而是使用多个**专家（expert）**FFN层和一个**门控网络（gating network，路由 router）**来选择每个token应该激活哪些专家。

- 门控函数为每个专家计算一个路由分数，并选择top-$k$（通常$k = 1$或$k = 2$）：

$$G(x) = \text{TopK}(\text{softmax}(W_g x))$$

- 只有被选中的专家处理该token，因此计算成本随$k$（活跃专家的数量）缩放，而不是随专家总数$E$。一个具有8个专家且top-2路由的模型具有稠密模型的4倍参数，但只有2倍计算量。

![MoE层：输入token通过路由器计算每个专家的分数，选择top-2专家，它们的输出按门控分数加权并求和](../../images/moe_layer.svg)

- MoE中一个关键挑战是**负载均衡（load balancing）**：如果路由器将大多数token发送给少数几个热门专家，其他专家就被浪费了。训练时添加一个辅助的**负载均衡损失（load balancing loss）**以鼓励均匀的专家利用率：

$$\mathcal{L}_{\text{balance}} = E \cdot \sum_{i=1}^{E} f_i \cdot p_i$$

- 其中$f_i$是分配给专家$i$的token比例，$p_i$是专家$i$的平均路由概率。当token比例和概率都均匀时（各自等于$1/E$），该乘积最小化。

- **专家并行（Expert parallelism）**将不同的专家分布到不同的加速器上。在前向传播期间，一个全到全的通信步骤将token路由到托管其分配专家的设备，然后将结果路由回来。这种通信成本是MoE在大规模下的主要工程挑战。Switch Transformer、Mixtral和GShard等模型都使用MoE以实用的推理成本实现强大的性能。

- 构建模型只是工作的一半；衡量模型是否有效是另一半。NLP的评估异常困难，因为语言是模糊的、主观的和开放式的。

- 一种翻译可以以许多不同的方式正确。一个摘要即使与参考答案没有任何完全相同的词也可能是好的。

- 一个聊天机器人的回复可以是乐于助人、无害且诚实的，但理性的评估者仍可能意见不一。

- **精确匹配（Exact Match，EM）**是最简单的指标：模型的输出是否与标准答案完全匹配？它用于具有简短、明确答案的任务，如抽取式问答（SQuAD）或封闭形式数学。

- EM很苛刻；"New York City"和"new york city"在不进行规范化的情况下无法匹配——但它的简单性使其明确无误。

- **Token级指标**将NLP视为token级的分类问题，使用第06章中的精确率、召回率和F1。

- **精确率（Precision）**衡量模型预测的token中有多少比例是正确的：$P = \text{TP} / (\text{TP} + \text{FP})$。一个预测非常少的实体但都正确的模型具有高精确率。

- **召回率（Recall）**衡量标准答案中的token有几分之几被模型找到：$R = \text{TP} / (\text{TP} + \text{FN})$。一个将每个token都预测为实体的模型具有完美的召回率但糟糕的精确率。

- **F1**是精确率和召回率的调和平均值：

$$F_1 = \frac{2PR}{P + R}$$

- 调和平均（而非算术平均）惩罚不平衡：如果$P$或$R$任何一个低，$F_1$就低。对于NER（第02章），F1按实体类型计算，然后在各类型上做宏平均。对于词性标注，token级准确率更常见，因为每个token都有一个标签。

- **片段级F1（Span-level F1）**（SQuAD中使用）比较预测片段中的token集合与标准答案片段中的token集合。这比精确匹配更宽容：如果标准答案是"the Eiffel Tower"而模型预测"Eiffel Tower"，则片段F1很高（5个token中4个重叠），即使EM为零。

- **BLEU**（双语评估替补，Bilingual Evaluation Understudy，Papineni等人，2002）是机器翻译的经典指标。它衡量候选翻译与一个或多个参考翻译之间的n元语法重叠。分数结合了多个n元语法级别（一元至四元）的精确率和一个长度惩罚：

$$\text{BLEU} = \text{BP} \cdot \exp\!\left(\sum_{n=1}^{N} w_n \log p_n\right)$$

- 其中$p_n$是**修正n元语法精确率（modified n-gram precision）**：候选翻译中每个n元语法的计数被截断为其在任何参考文献中的最大计数，防止像"the the the the"这样的退化候选翻译获得高分。权重$w_n$通常是均匀的（$w_n = 1/N$，其中$N = 4$）。

- **长度惩罚（Brevity penalty）**$\text{BP} = \min(1, \exp(1 - r/c))$惩罚比参考答案短的候选翻译（$c$是候选长度，$r$是参考长度）。没有它，模型可以通过输出极少、极安全的词来获得高精确率。

- BLEU在语料库层面（对许多句子取平均）与人类判断的相关性尚可，但在句子层面相关性较差。

- 它奖励精确的n元语法匹配，但会错过有效的释义："the cat is on the mat"和"a feline sits atop the rug"在表达相同含义的同时，二元语法重叠为零。

- BLEU还完全忽略了召回率——一个只生成最常见词的候选翻译在精确率上得分很高。

- **ROUGE**（面向召回率的摘要评估替补，Recall-Oriented Understudy for Gisting Evaluation，Lin，2004）是摘要生成的标准指标。与强调精确率的BLEU不同，ROUGE强调召回率：参考摘要中的n元语法有多少比例出现在候选摘要中？

- **ROUGE-N**计算n元语法的召回率：$\text{ROUGE-N} = \frac{|\text{n-grams}_{\text{ref}} \cap \text{n-grams}_{\text{cand}}|}{|\text{n-grams}_{\text{ref}}|}$。ROUGE-1（一元）和ROUGE-2（二元）最为常见。

- ROUGE-L使用候选与参考之间的**最长公共子序列（Longest Common Subsequence，LCS）**，它捕捉了句子级的词序，而不需要连续的匹配。

- LCS长度按参考长度归一化给出召回率，按候选长度归一化给出精确率，F-measure将两者结合。

- LCS通过动态规划在$O(mn)$时间内计算（类似于第02章的编辑距离）：

$$R_{\text{LCS}} = \frac{\text{LCS}(X, Y)}{m}, \quad P_{\text{LCS}} = \frac{\text{LCS}(X, Y)}{n}, \quad F_{\text{LCS}} = \frac{(1 + \beta^2) R_{\text{LCS}} P_{\text{LCS}}}{R_{\text{LCS}} + \beta^2 P_{\text{LCS}}}$$

- 其中$m$和$n$是参考和候选的长度，$\beta$通常设置为偏向召回率（$\beta \to \infty$给出纯召回率）。

- **METEOR**（带显式排序的翻译评估指标，Metric for Evaluation of Translation with Explicit ORdering，Banerjee和Lavie，2005）通过纳入同义词、词干提取和词序来解决BLEU的弱点。

- 它首先使用精确匹配、词干匹配（通过第02章的Porter词干提取器）和同义词匹配（通过第01章的WordNet）在候选和参考之间对齐词语。

- 然后，它计算偏向召回率的一元精确率和召回率的调和平均，并应用碎片惩罚，惩罚那些匹配词以与参考不同的顺序出现的候选。

- **ChrF**（字符n元语法F分数，Character n-gram F-score）在字符n元语法而非词n元语法上计算F分数。这使其对形态变异具有鲁棒性（对第01章中的黏着语至关重要），并部分处理了分词差异。ChrF++在字符n元语法的基础上添加了词二元语法。

- 它已成为机器翻译中与BLEU并列推荐的指标，尤其适用于形态丰富的语言。

- **困惑度（Perplexity）**（第02章）衡量语言模型预测保留测试集的能力。它是语言模型的标准内在指标：$\text{PPL} = \exp(-\frac{1}{N} \sum_{i} \log P(w_i \mid w_{<i}))$。越低越好。

- 困惑度仅在使用相同分词方式的模型之间可比，因为不同的分词器对同一文本产生不同的序列长度$N$。

- 词表更大的模型往往每个token的困惑度更低，但每个句子处理的token更少。

- **每字节比特数（Bits-per-byte，BPB）**按文本中的UTF-8字节数而非token数进行归一化，使其独立于分词方式：

```math
\text{BPB} = \frac{-\sum_{i} \log_2 P(w_i \mid w_{<i})}{\text{number of UTF-8 bytes}}
```

- **BERTScore**（Zhang等人，2020）通过在嵌入空间中计算相似度，超越了表面级的n元语法匹配。候选文本中的每个token使用上下文嵌入（通常来自预训练的BERT模型）的余弦相似度与参考文本中最相似的token匹配。分数被聚合为精确率、召回率和F1：

$$R_{\text{BERT}} = \frac{1}{|r|} \sum_{r_i \in r} \max_{c_j \in c} \cos(r_i, c_j), \quad P_{\text{BERT}} = \frac{1}{|c|} \sum_{c_j \in c} \max_{r_i \in r} \cos(c_j, r_i)$$

- 其中$r_i$和$c_j$是参考和候选token的上下文嵌入。这捕捉了n元语法指标错过的语义相似性："automobile"和"car"得分高，因为它们的BERT嵌入相似，即使它们没有任何共同字符。

- **BLEURT**（Sellam等人，2020）进一步通过在人类质量判断上微调BERT模型。给定参考和候选文本对，它输出一个标量质量分数。BLEURT在合成数据（参考翻译的随机扰动，由BLEU和METEOR等指标评分）上训练，然后在人类评分上微调。它与人类判断的相关性比任何表面级指标都好。

- **COMET**（跨语言优化的翻译评估指标，Crosslingual Optimized Metric for Evaluation of Translation，Rei等人，2020）是机器翻译的学习型指标，它以源句子、参考和候选为条件——而不仅仅是参考和候选。它使用多语言编码器（XLM-R）嵌入三者，并预测质量分数。通过看到源文本，COMET能够检测仅参考指标会错过的含义错误（例如，一个流利但事实错误的翻译）。

- **LLM-as-judge**（以LLM为裁判）是现代大规模评估方法。不计算与参考答案对比的指标，而是提示一个强大的语言模型（GPT-4、Claude）评估模型输出的质量。裁判接收输入、模型的响应以及可选的参考回答，并生成评分（例如1-5分）或成对偏好（回答A优于回答B）。

- **成对比较（Pairwise comparison）**（Chatbot Arena中使用）是最可靠的LLM-as-judge格式。裁判看到两个回答并选择更好的一个，而不是分配绝对分数。这避免了校准问题（不同裁判对"3/5分"可能有不同的基线）。结果聚合为**Elo评分（Elo ratings）**（源自国际象棋），每个模型以基础评分开始，根据与其他模型的胜负得失积分。模型$A$对模型$B$的预期胜率是：

$$P(A \succ B) = \frac{1}{1 + 10^{(R_B - R_A) / 400}}$$

- 其中$R_A, R_B$是Elo评分。每次比较后更新评分：$R_A' = R_A + K(S - P(A \succ B))$，其中$S \in \{0, 1\}$是实际结果，$K$控制更新幅度。持续击败强敌的模型快速上升；输给弱敌的模型下降。

- **位置偏置（Position bias）**是LLM裁判的一个已知问题：它们倾向于偏好第一个呈现的回答（或在某些模型中，第二个呈现的回答）。**交换（Swapping）**（以两种顺序各评估一对一次）并取平均结果可以缓解此问题。

- **冗长偏置（Verbosity bias）**是另一个问题：裁判倾向于偏好更长、更详细的回答，即使简洁的回答更好。

- **自一致性（Self-consistency）**检查裁判对同一输入的多次评估是否给出一致的评分。高方差表明评估信号噪声大。

- **标注者间一致性（Inter-annotator agreement）**（Cohen's kappa或Krippendorff's alpha）衡量多个裁判是否一致，提供评估可靠性的上限。

- **数据污染（Contamination）**是一个关键关注点：如果评估数据出现在模型的训练集中，基准分数就会被夸大且无意义。

- 这对于在网页抓取数据上训练的LLM尤其成问题，因为流行的基准很可能存在。缓解策略包括：使用不公开发布的保留测试集，创建定期重新生成问题的动态基准，**金丝雀字符串（canary strings）**（嵌入基准数据中的唯一标识符，用于检测泄漏），以及比较受污染子集与干净子集上的性能。

- **标准NLU基准**评估跨多样化任务的语言理解能力。

- **GLUE**（通用语言理解评估，General Language Understanding Evaluation）和**SuperGLUE**是多任务基准，涵盖情感分析（SST-2）、文本相似度（STS-B）、自然语言推理（MNLI、RTE）、共指消解（WSC）和问答（BoolQ）。

- 模型在每个任务上单独评估，并按一个聚合指标打分。GLUE现在被认为已经饱和（模型在大多数任务上超过人类性能）；SuperGLUE仍然更具挑战性。

- **MMLU**（大规模多任务语言理解，Massive Multitask Language Understanding）使用多项选择题，评估跨57个学科（数学、历史、法律、医学、计算机科学等）的知识和推理能力。

- 它测试模型在预训练期间是否吸收了广泛的知识。分数按学科报告并做宏平均。

- **MMLU-Pro**添加了更难的、需要多步推理的问题，有10个答案选项而不是4个。

- **HellaSwag**通过要求模型选择场景最合理的续写来测试常识推理。错误答案是通过模型对抗生成（adversarially generated）的，表面合理但在语义上错误。

- **WinoGrande**使用仅一字之差的最小对比对来测试常识共指消解。

- **ARC**（AI2推理挑战，AI2 Reasoning Challenge）使用小学科学问题的简单集和挑战集，测试知识和推理能力。

- **推理和数学基准**评估将强大LLM与弱LLM区分开来的问题解决能力。

- **GSM8K**（小学数学8K，Grade School Math 8K）包含8,500个需要多步算术推理的小学数学应用题。它是基础数学推理和评估思维链提示（第04章）的标准基准。

- **MATH**是一个更难的竞赛级数学问题数据集，涵盖代数、数论、几何、组合和概率。问题需要多步符号推理，MATH-500是一个常用的500道题的子集。

- **AIME**（美国数学邀请赛，American Invitational Mathematics Examination）问题是竞赛级别的：正确求解需要跨多步的深层数学推理。DeepSeek-R1在AIME 2024上得分79.8%，表明经过RL训练的推理模型（第05章）可以接近强人类选手水平。

- **HumanEval**和**MBPP**（主要为基础编程问题，Mostly Basic Programming Problems）通过检查模型代码是否通过单元测试来评估代码生成。HumanEval包含164个Python问题，带有函数签名和文档字符串；模型必须生成函数体。

- 指标是**pass@k**：$k$个生成解决方案中至少有一个通过所有测试的概率。对于单个样本：

$$\text{pass@}k = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}$$

- 其中$n$是生成样本的总数，$c$是通过的样本数。该公式校正了简单地取$k$个样本中最优者所带来的偏差。

- **SWE-bench**更进一步，评估模型是否能够通过修改现有代码库来解决真实的GitHub问题——这是对实际软件工程能力的更严格的测试。

- **GPQA**（研究生级防Google问答，Graduate-Level Google-Proof QA）包含生物学、物理学和化学领域中对领域专家也困难的专业级问题。它测试模型是否具有真正的理解，而不仅仅是模式匹配。"Diamond"子集是最难的。

- **安全性和对齐基准**评估模型是否乐于助人、无害和诚实。

- **TruthfulQA**测试模型是否会重复常见的误解。问题设计使得最常见的互联网答案都是错误的（例如，"如果吞下口香糖会发生什么？"常见的误解是它会在体内停留7年，但真实的答案是它会正常通过消化系统）。那些记忆了流行但不正确说法的模型得分很低。

- **BBQ**（QA偏置基准，Bias Benchmark for QA）测试跨年龄、性别、种族和宗教等类别的社会偏见。问题被构造成一个带有偏见的模型将系统性地选择刻板印象答案。**Toxigen**评估模型对特定人口群体生成有毒内容的倾向。

- **MT-Bench**使用80个精心设计的问题评估多轮对话能力，涵盖写作、角色扮演、推理、数学、编码、信息提取、STEM和人文学科。一个LLM裁判（GPT-4）按1-10分制评分。多轮格式测试模型是否能够跟进、维护上下文并处理澄清请求。

- **Chatbot Arena**（LMSYS）使用真实用户对匿名模型进行盲测成对比较。用户提交提示并在不知道哪个模型生成回答的情况下投票选择更好的回答。由此产生的Elo排行榜被认为是对通用LLM质量最有生态效度的评估，因为它反映了真实用户在多样化、未经策划的提示上的偏好。

- **AlpacaEval**通过在一组固定的指令上将模型输出与参考模型（GPT-4）进行成对比较来自动化评估。一个裁判模型决定胜率。

- **AlpacaEval 2.0**使用长度控制的胜率来校正冗长偏置。

- **任务特定评估**需要为专门领域量身定制指标。

- **词错误率（Word Error Rate，WER）**用于语音识别：$\text{WER} = (S + D + I) / N$，其中$S$、$D$、$I$分别是替换（substitution）、删除（deletion）和插入（insertion）错误，$N$是参考词的数量。这是编辑距离（第02章）按参考长度归一化后应用于词级别。

- **槽位F1（Slot F1）**用于任务导向的对话系统，衡量模型从用户话语中正确提取结构化信息的程度（例如，从"Book me a flight to Paris tomorrow"中提取"destination: Paris"和"date: tomorrow"）。

- **引用准确性（Citation accuracy）**用于RAG系统（第05章），检查模型生成的引用是否确实支持所做的声明。声明与检索到的段落进行验证，该指标统计完全支持、部分支持或不支持的声明的比例。

- **评估陷阱**很常见，可能使整个基准比较无效。

- **应试教学（Teaching to the test）**：优化基准性能而非真正能力。一个在MMLU风格多项选择题上微调的模型会在MMLU上得分高，但在以开放式格式提出的相同问题上可能失败。

- **指标投机（Metric gaming）**：模型可以被优化以产生在自动指标上得分高（高BLEU、低困惑度）但并非真正好的输出。BLEU最优的翻译通常是一个安全、通用的释义，而不是自然、流畅的翻译。

- **基准饱和（Benchmark saturation）**：当模型在基准上接近或超过人类性能时，该基准就不再提供信息。GLUE、SQuAD 1.1和其他几个基准现在已经饱和。

- 该领域不断创建更难的基准，但创建、饱和和替换的循环使得纵向比较变得困难。

- **人类评估（Human evaluation）**仍然是黄金标准，但昂贵、缓慢且难以复现。不同的标注者池（众包工作者 vs 领域专家，不同文化，不同语言）产生不同的判断。报告标注者间一致性和标注者人口统计信息对于可复现性至关重要。

1. 从零实现一个完整的Transformer编码器块（多头注意力、前馈网络、残差连接、层归一化）。将其应用于一个简单的序列分类任务。
```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

def layer_norm(x, gamma, beta, eps=1e-5):
    mean = x.mean(axis=-1, keepdims=True)
    var = x.var(axis=-1, keepdims=True)
    return gamma * (x - mean) / jnp.sqrt(var + eps) + beta

def multi_head_attention(Q, K, V, W_q, W_k, W_v, W_o, n_heads):
    B, T, D = Q.shape
    head_dim = D // n_heads

    q = Q @ W_q  # (B, T, D)
    k = K @ W_k
    v = V @ W_v

    # Reshape to (B, n_heads, T, head_dim)
    q = q.reshape(B, T, n_heads, head_dim).transpose(0, 2, 1, 3)
    k = k.reshape(B, T, n_heads, head_dim).transpose(0, 2, 1, 3)
    v = v.reshape(B, T, n_heads, head_dim).transpose(0, 2, 1, 3)

    scores = q @ k.transpose(0, 1, 3, 2) / jnp.sqrt(head_dim)
    weights = jax.nn.softmax(scores, axis=-1)
    out = (weights @ v).transpose(0, 2, 1, 3).reshape(B, T, D)
    return out @ W_o, weights

def transformer_block(x, params):
    # Pre-norm multi-head self-attention
    normed = layer_norm(x, params['ln1_g'], params['ln1_b'])
    attn_out, weights = multi_head_attention(
        normed, normed, normed,
        params['W_q'], params['W_k'], params['W_v'], params['W_o'],
        n_heads=4
    )
    x = x + attn_out

    # Pre-norm feed-forward
    normed = layer_norm(x, params['ln2_g'], params['ln2_b'])
    ff = jax.nn.gelu(normed @ params['W1'] + params['b1'])
    ff = ff @ params['W2'] + params['b2']
    x = x + ff
    return x, weights

# Initialise parameters
d_model, d_ff, n_heads = 32, 128, 4
key = jax.random.PRNGKey(42)
keys = jax.random.split(key, 10)

params = {
    'W_q': jax.random.normal(keys[0], (d_model, d_model)) * 0.05,
    'W_k': jax.random.normal(keys[1], (d_model, d_model)) * 0.05,
    'W_v': jax.random.normal(keys[2], (d_model, d_model)) * 0.05,
    'W_o': jax.random.normal(keys[3], (d_model, d_model)) * 0.05,
    'ln1_g': jnp.ones(d_model), 'ln1_b': jnp.zeros(d_model),
    'ln2_g': jnp.ones(d_model), 'ln2_b': jnp.zeros(d_model),
    'W1': jax.random.normal(keys[4], (d_model, d_ff)) * 0.05,
    'b1': jnp.zeros(d_ff),
    'W2': jax.random.normal(keys[5], (d_ff, d_model)) * 0.05,
    'b2': jnp.zeros(d_model),
}

# Test with random input
x = jax.random.normal(keys[6], (2, 8, d_model))  # batch=2, seq_len=8
out, attn_weights = transformer_block(x, params)
print(f"Input shape:  {x.shape}")
print(f"Output shape: {out.shape}")
print(f"Attention weights shape: {attn_weights.shape}")  # (B, n_heads, T, T)

# Visualise attention patterns for each head
fig, axes = plt.subplots(1, 4, figsize=(16, 3.5))
for h in range(4):
    im = axes[h].imshow(attn_weights[0, h], cmap='Blues', vmin=0)
    axes[h].set_title(f"Head {h}")
    axes[h].set_xlabel("Key pos"); axes[h].set_ylabel("Query pos")
plt.suptitle("Multi-Head Attention Patterns")
plt.tight_layout(); plt.show()
```

2. 实现因果（自回归）注意力掩码，并将其与双向注意力进行比较。展示掩码如何阻止信息从未来的token流向过去的token。
```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

def attention(Q, K, V, mask=None):
    d_k = Q.shape[-1]
    scores = Q @ K.T / jnp.sqrt(d_k)
    if mask is not None:
        scores = jnp.where(mask, scores, -1e9)
    weights = jax.nn.softmax(scores, axis=-1)
    return weights @ V, weights

seq_len, d_model = 6, 8
key = jax.random.PRNGKey(0)
k1, k2, k3 = jax.random.split(key, 3)
Q = jax.random.normal(k1, (seq_len, d_model))
K = jax.random.normal(k2, (seq_len, d_model))
V = jax.random.normal(k3, (seq_len, d_model))

# Bidirectional (encoder-style): all positions visible
bidir_mask = jnp.ones((seq_len, seq_len), dtype=bool)
bidir_out, bidir_weights = attention(Q, K, V, bidir_mask)

# Causal (decoder-style): only past and current positions visible
causal_mask = jnp.tril(jnp.ones((seq_len, seq_len), dtype=bool))
causal_out, causal_weights = attention(Q, K, V, causal_mask)

fig, axes = plt.subplots(1, 3, figsize=(14, 4))
tokens = [f"t{i}" for i in range(seq_len)]

axes[0].imshow(bidir_weights, cmap='Blues', vmin=0, vmax=0.5)
axes[0].set_title("Bidirectional Attention\n(BERT-style)")
axes[0].set_xticks(range(seq_len)); axes[0].set_xticklabels(tokens)
axes[0].set_yticks(range(seq_len)); axes[0].set_yticklabels(tokens)

axes[1].imshow(causal_mask.astype(float), cmap='Greys', vmin=0, vmax=1)
axes[1].set_title("Causal Mask\n(1 = allowed, 0 = blocked)")
axes[1].set_xticks(range(seq_len)); axes[1].set_xticklabels(tokens)
axes[1].set_yticks(range(seq_len)); axes[1].set_yticklabels(tokens)

axes[2].imshow(causal_weights, cmap='Blues', vmin=0, vmax=0.5)
axes[2].set_title("Causal Attention\n(GPT-style)")
axes[2].set_xticks(range(seq_len)); axes[2].set_xticklabels(tokens)
axes[2].set_yticks(range(seq_len)); axes[2].set_yticklabels(tokens)

for ax in axes:
    ax.set_xlabel("Key"); ax.set_ylabel("Query")
plt.tight_layout(); plt.show()

# Verify: in causal attention, output at position i depends only on positions <= i
print("Causal attention weight at position 2 (should only attend to 0, 1, 2):")
```

3. 实现LoRA（低秩适配），展示它如何用比全量微调少得多的可训练参数来修改权重矩阵。
```python
import jax
import jax.numpy as jnp

d_model = 256
rank = 4  # LoRA rank (much smaller than d_model)

key = jax.random.PRNGKey(42)
k1, k2, k3 = jax.random.split(key, 3)

# Original frozen weight matrix
W_frozen = jax.random.normal(k1, (d_model, d_model)) * 0.02

# LoRA matrices (only these are trainable)
B = jnp.zeros((d_model, rank))       # initialised to zero
A = jax.random.normal(k2, (rank, d_model)) * 0.01  # random init

# Forward pass: W_effective = W_frozen + B @ A
x = jax.random.normal(k3, (8, d_model))

# Without LoRA
y_original = x @ W_frozen.T

# With LoRA
W_effective = W_frozen + B @ A
y_lora = x @ W_effective.T

# Parameter counts
full_params = d_model * d_model
lora_params = d_model * rank + rank * d_model  # B + A

print(f"Model dimension: {d_model}")
print(f"LoRA rank: {rank}")
print(f"Full fine-tuning parameters: {full_params:,}")
print(f"LoRA parameters: {lora_params:,}")
print(f"Parameter reduction: {full_params / lora_params:.1f}x")
print(f"\nSince B is initialised to zeros, initial LoRA output matches original:")
print(f"  Max difference: {jnp.abs(y_original - y_lora).max():.2e}")

# Simulate training: only update A and B
def lora_forward(A, B, W_frozen, x):
    return x @ (W_frozen + B @ A).T

def dummy_loss(A, B, W_frozen, x, target):
    pred = lora_forward(A, B, W_frozen, x)
    return jnp.mean((pred - target) ** 2)

# Target: some transformation of x
target = x @ jax.random.normal(jax.random.PRNGKey(99), (d_model, d_model)).T * 0.02

grad_fn = jax.jit(jax.grad(dummy_loss, argnums=(0, 1)))
lr = 0.01

for step in range(200):
    gA, gB = grad_fn(A, B, W_frozen, x, target)
    A = A - lr * gA
    B = B - lr * gB

loss_before = dummy_loss(jnp.zeros_like(A), jnp.zeros_like(B), W_frozen, x, target)
loss_after = dummy_loss(A, B, W_frozen, x, target)
print(f"\nLoss before LoRA: {loss_before:.6f}")
print(f"Loss after LoRA:  {loss_after:.6f}")
print(f"Effective weight change rank: {jnp.linalg.matrix_rank(B @ A)}")
```
